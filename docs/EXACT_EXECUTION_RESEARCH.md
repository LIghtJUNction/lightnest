## 从原语到受限的完整 ELF 执行

`exact_x86.py` 将已有 `ExactBitRAM` 与 `FixedWordAdder` 接入一个有界 x86-64
解释器。寄存器按位保存在显式 RAM 中；64 位加减由两段 32 位固定加法器传递进位。
实现包括部分寄存器写入与 32 位零扩展、条件标志、直接分支、循环、调用栈、静态
ELF 段读写，以及标准输入 read、标准输出/错误 write 和 exit。

宿主仍负责 ELF 加载、iced-x86 译码、地址映射、分派和控制流；这不是全部编译进
网络权重的 CPU，也没有训练或改变 RGB 的权重。每次 run 都从新的机器状态开始。
状态绑定原始文件、输入、机器规格、精度与步数预算；没有原生执行或参考状态回填。

这一定位与 [Qwenputer 作者描述的完整权重内 RV32 CPU](https://divagr.com/blog/qwenputer)
有明显范围差异；不能把其能力或性能结论移用于这里。指令语义的规范入口为
[Intel 64 / IA-32 软件开发手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)。

边界固定如下：只接受小型、静态、little-endian x86-64 ET_EXEC；不支持动态链接、
argv、任意系统调用或可写可执行段。每映射最多 4096 字节，总映射最多 16384 字节，
包括一个 4096 字节的虚拟栈。未初始化的寄存器/栈、未定义标志、未覆盖指令、越界、
权限错误与预算耗尽分别返回显式失败，不回退到宿主执行。

## 冻结的差分实验

`tools/probe_exact_x86.py prepare` 先固定所有二进制、输入、种子、源码、依赖哈希和
编译命令，再由 evaluate 执行。主评测没有根据原生答案修改机器状态。

32 个 C 编译变体来自 8 个本地编写的功能族：32/64 位加减、逻辑、无符号选择、
有符号选择、循环、栈内数组与函数调用。分别使用 GCC / Clang 和 O0 / O2；每个
变体使用 8 个边界输入与 3 个固定种子各产生的 4 个随机输入。另加原有生成课程的
4 个完整 ELF。因此功能族多样性为 8 类，编译变体仅用于覆盖编译器与优化差异。

当前接受记录为 `frozen-v3/`；它在 C 包装入口中建立独立的 ELF BSS 栈，原生与张量
执行使用相同的栈位置，不依赖最初的操作系统栈。`frozen-v1/` 与 `frozen-v2/` 保留
前两次运行及其虚拟栈假设；多轮使用相同数值输入，不能相加当作独立样本。

| 检查 | frozen-v3 实测 |
| --- | ---: |
| 完整 ELF | 36 |
| 原生程序与输入组合 | 644 |
| FP32 / BF16 张量执行 | 1288 |
| 累计张量指令步数 | 53038 |
| 输出字节及退出状态与原生执行不一致 | 0 |
| 跨精度最终数据内存不一致 | 0 |
| 加法器故意损坏、拒绝不支持输入、预算耗尽等负对照 | 全部检测到 |

比较包含完整 stdout、stderr 和退出码。原生参照独立使用现有 bubblewrap 沙箱。
主评测有 644 次原生执行，负对照另用 1 次。耗时只保留为机器负载下的成本记录，
没有做速度优势或稳定吞吐的结论。所有结果仅适用于冻结的程序、输入与实现。

## 新发现的环境依赖反例

准备语义修复样本时，`gcc-O0-arithmetic32` 的文件偏移 4222 翻转第 4 位，将
`mov [rbp-8],esi` 改成了 `mov [rbp-8],esp`。程序把操作系统安排的栈地址当作参数。
相同二进制与相同输入的五次独立原生执行，stdout 在 `e0ffffff` 与 `c0ffffff`
之间变化；固定虚拟栈的解释器则返回自己的确定结果。

原始反例、完整指令轨迹与重复原生结果保存在 `counterexample-4222-4/`。它说明当前
虚拟环境与 Linux 进程环境并不相同，观察栈地址等环境信息的程序不能据本轮结果
宣称等价。差分通过不允许把内部执行器作为所有候选的最终正确性保证。

第二个反例 `gcc-O2-memory` 的偏移 4243 翻转第 3 位后重写了 SPL。其原生执行多数
以 139 退出，偶尔正常返回；五次重复并不能可靠区分这种环境依赖与稳定的实现错误。
`premise-audit.json` 只平移张量解释器的初始栈 16 字节，保持程序和输入不变：原程序
的结果不变，两份损坏程序的输出或完成状态都变化，直接否定了任意初始栈等价的假设。

因此语料改为由 ELF 入口主动建立同一个私有栈，形成明确的环境契约，再重新冻结
和差分执行。旧反例及两次中止的构造记录保留。构造器仍会记录重复执行发现的输出
不稳定；稳定分歧会终止构造，不会直接删除继续训练。重复检查本身不能证明确定性。

## 下一关：真实训练后的语义编辑

`tools/research_exact_repair.py` 在本地编写 C 程序的 operation 函数内注入一个位错误。
仅接纳完整运行且改变可见输出、并经独立原生执行核对的样本。输入模型的是完整
损坏 ELF、统一修复请求和四个可见输入/输出；不提供故障位置、干净文件或隐藏输出。
干净字节只用于训练监督和事后身份核对。

功能族划分事先固定：加减、逻辑和循环训练；无符号选择与数组验证；有符号选择和
函数调用测试。同一功能族的编译变体留在同一划分。构造得到 96 个训练样本、48 个
验证样本和 48 个测试样本；每程序按冻结哈希选择两个验证/测试样本，因此本轮公开
验证实际覆盖 16/48 项，神经测试查询为 0/48 项。

模型宽度 32，红区深度 2，共 78368 个参数。所有训练使用同一个种子 20261029。
初始 512 步未拟合训练集后，增加两组同预算的 4096 步对照：原 balanced 损失与
直接优化单次编辑位置排名的 ranking 损失。它们使用相同初始化、样本顺序和学习率；
第二个对照再将整个替换字节预测改为 XOR 位翻转预测，保持参数数目不变。这些是
单种子、公开奖励反馈后的跟进实验，不能当作多种子稳定性或独立预注册证据。

`DeltaRGBPolicy` 只把实际损坏输入的位用于输出表示转换，位置和翻转位均由网络学习。
没有提供干净字节或反向位翻转规则；旧 RGB 检查点的语义及默认加载器保持原样。

验证先比较未训练权重与候选的蓝区一次动作：候选必须在损坏样本上至少达到 25% 可见
执行成功率，且严格高于未训练权重，才打开测试集。测试再比较同一权重、同一候选
预算下的原生验证和张量验证；返回的候选仍接受独立原生隐藏输入检查。若验证失败，
保留失败，测试查询数维持为 0。

## 神经结果：全部未通过

每 256 步按固定公开验证选择候选。下表列的是选择得到的最好验证分数，不是独立测试
分数；4096 步的方案各检查了 16 个阶段点，不能据此计算无选择偏差的置信区间。

| 配置 | 更新数 | 最好验证成功 | 状态 |
| --- | ---: | ---: | --- |
| 未训练权重 | 0 | 0/16 | 基线 |
| balanced，完整替换字节 | 512 | 0/16 | 未通过 |
| balanced，完整替换字节 | 4096 | 0/16 | 未通过 |
| ranking，完整替换字节 | 4096 | 1/16 | 未通过 |
| ranking，XOR 位翻转 | 4096 | 1/16 | 未通过 |

通过门槛是至少 4/16 且超过各自初始权重。本轮所有候选都保持 `not_promoted`，没有
打开神经测试集，也没有开展训练后候选的原生/张量验证器盲测对照。支持的核心指令
能精确执行，不表示网络已经学会选择正确编辑。

最终 4096 步权重的训练诊断从每个训练程序取两个预先固定样本，共 32 项：ranking
替换方案定位正确 30/32，完整恢复原始字节仅 11/32；XOR 方案分别为 28/32 和 12/32。
在 16 个验证样本中，两份最终权重的精确原字节修复均为 0，给定正确位置后的替换
字节预测也均为 0/16。后者只用于事后定位失败来源，不作为推理时的输入。

这些结果支持“训练任务拟合提升尚未转化为未见功能族修复”的有限判断，不能证明
增加训练永远无效，也不能把 0 到 1/16 的公开验证变化解释为可靠能力突破。下一关
仍是更强的行为监督、程序多样性与独立泛化证据，论文贡献尚未成立。

原始记录分别位于 `repair-v4/`、`repair-balanced-4096/`、`repair-ranking-4096/` 和
`repair-ranking-xor-4096/`。`repair-v1/`、`repair-v2/` 保留中止原因；`repair-v3/` 保留
数据冻结。v4 在任何神经训练前重新冻结验证方法，任务内容哈希保持不变。历史方案
必须配合各自源码快照和依赖锁文件使用，不能用当前入口绕过旧候选的源码身份校验。

最终本地统一检查通过：299 个源码文件和 134 + 19 + 77 + 23 = 253 项测试。没有
重跑远程 CI，没有执行可选 Lean 完整证明，没有修改或重打包自解释 ELF。

## 复现入口

所有输出目录必须为仓库外的新路径。先运行源码检查：

```bash
uv sync --locked
uv run --locked python tools/check.py
```

冻结并差分执行：

```bash
uv run --locked python tools/probe_exact_x86.py prepare --out "$OUT/core"
uv run --locked python tools/probe_exact_x86.py evaluate --out "$OUT/core"
```

通过后构造新修复语料、训练并按门槛检查：

```bash
uv run --locked python tools/research_exact_repair.py prepare \
  --out "$OUT/repair" --parent "$OUT/core"
uv run --locked python tools/research_exact_repair.py train --out "$OUT/repair"
uv run --locked python tools/research_exact_repair.py evaluate --out "$OUT/repair"
```

复用经哈希验证的任务池进行公开验证跟进时使用新目录：

```bash
uv run --locked python tools/research_exact_repair.py refreeze \
  --out "$OUT/ranking-xor" --parent "$OUT/repair" \
  --steps 4096 --objective ranking --edit-encoding xor
uv run --locked python tools/research_exact_repair.py train --out "$OUT/ranking-xor"
uv run --locked python tools/research_exact_repair.py evaluate --out "$OUT/ranking-xor"
```

如果父实验已经查询神经测试，refreeze 会拒绝把它重新包装成新的盲测。
