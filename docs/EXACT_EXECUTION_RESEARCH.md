## 从原语到受限的完整 ELF 执行

`exact_x86.py` 将已有 `ExactBitRAM` 与 `FixedWordAdder` 接入一个有界 x86-64
解释器。寄存器按位保存在显式 RAM 中；64 位加减由两段 32 位固定加法器传递进位。
实现包括部分寄存器写入与 32 位零扩展、条件标志、直接分支、循环、调用栈、静态
ELF 段读写，以及标准输入 read、标准输出/错误 write 和 exit。

宿主仍负责 ELF 加载、iced-x86 译码、地址映射、分派和控制流；这不是全部编译进
网络权重的 CPU，也没有训练或改变 RGB 的权重。每次 run 都从新的机器状态开始。
状态绑定原始文件、输入、机器规格、精度与步数预算；没有原生执行或参考状态回填。

这一定位与 [Qwenputer 作者描述的完整权重内 RV32 CPU](https://divagr.com/blog/qwenputer)
有明显范围差异；不能把其能力或性能结论移用于这里。指令语义的规范入口为
[Intel 64 / IA-32 软件开发手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)。

边界固定如下：只接受小型、静态、little-endian x86-64 ET_EXEC；不支持动态链接、
argv、任意系统调用或可写可执行段。每映射最多 4096 字节，总映射最多 16384 字节，
包括一个 4096 字节的虚拟栈。未初始化的寄存器/栈、未定义标志、未覆盖指令、越界、
权限错误与预算耗尽分别返回显式失败，不回退到宿主执行。

## 冻结的差分实验

`archive/research/tools/probe_exact_x86.py prepare` 先固定所有二进制、输入、种子、源码、依赖哈希和
编译命令，再由 evaluate 执行。主评测没有根据原生答案修改机器状态。

32 个 C 编译变体来自 8 个本地编写的功能族：32/64 位加减、逻辑、无符号选择、
有符号选择、循环、栈内数组与函数调用。分别使用 GCC / Clang 和 O0 / O2；每个
变体使用 8 个边界输入与 3 个固定种子各产生的 4 个随机输入。另加原有生成课程的
4 个完整 ELF。因此功能族多样性为 8 类，编译变体仅用于覆盖编译器与优化差异。

当前接受记录为 `frozen-v3/`；它在 C 包装入口中建立独立的 ELF BSS 栈，原生与张量
执行使用相同的栈位置，不依赖最初的操作系统栈。`frozen-v1/` 与 `frozen-v2/` 保留
前两次运行及其虚拟栈假设；多轮使用相同数值输入，不能相加当作独立样本。

| 检查 | frozen-v3 实测 |
| --- | ---: |
| 完整 ELF | 36 |
| 原生程序与输入组合 | 644 |
| FP32 / BF16 张量执行 | 1288 |
| 累计张量指令步数 | 53038 |
| 输出字节及退出状态与原生执行不一致 | 0 |
| 跨精度最终数据内存不一致 | 0 |
| 加法器故意损坏、拒绝不支持输入、预算耗尽等负对照 | 全部检测到 |

比较包含完整 stdout、stderr 和退出码。原生参照独立使用现有 bubblewrap 沙箱。
主评测有 644 次原生执行，负对照另用 1 次。耗时只保留为机器负载下的成本记录，
没有做速度优势或稳定吞吐的结论。所有结果仅适用于冻结的程序、输入与实现。

## 新发现的环境依赖反例

准备语义修复样本时，`gcc-O0-arithmetic32` 的文件偏移 4222 翻转第 4 位，将
`mov [rbp-8],esi` 改成了 `mov [rbp-8],esp`。程序把操作系统安排的栈地址当作参数。
相同二进制与相同输入的五次独立原生执行，stdout 在 `e0ffffff` 与 `c0ffffff`
之间变化；固定虚拟栈的解释器则返回自己的确定结果。

原始反例、完整指令轨迹与重复原生结果保存在 `counterexample-4222-4/`。它说明当前
虚拟环境与 Linux 进程环境并不相同，观察栈地址等环境信息的程序不能据本轮结果
宣称等价。差分通过不允许把内部执行器作为所有候选的最终正确性保证。

第二个反例 `gcc-O2-memory` 的偏移 4243 翻转第 3 位后重写了 SPL。其原生执行多数
以 139 退出，偶尔正常返回；五次重复并不能可靠区分这种环境依赖与稳定的实现错误。
`premise-audit.json` 只平移张量解释器的初始栈 16 字节，保持程序和输入不变：原程序
的结果不变，两份损坏程序的输出或完成状态都变化，直接否定了任意初始栈等价的假设。

因此语料改为由 ELF 入口主动建立同一个私有栈，形成明确的环境契约，再重新冻结
和差分执行。旧反例及两次中止的构造记录保留。构造器仍会记录重复执行发现的输出
不稳定；稳定分歧会终止构造，不会直接删除继续训练。重复检查本身不能证明确定性。

## 真实训练后的语义编辑

`archive/research/tools/research_exact_repair.py` 在本地编写 C 程序的 operation 函数内注入一个位错误。
仅接纳完整运行且改变可见输出、并经独立原生执行核对的样本。输入模型的是完整
损坏 ELF、统一修复请求和四个可见输入/输出；不提供故障位置、干净文件或隐藏输出。
干净字节只用于训练监督和事后身份核对。

功能族划分事先固定：加减、逻辑和循环训练；无符号选择与数组验证；有符号选择和
函数调用测试。同一功能族的编译变体留在同一划分。构造得到 96 个训练样本、48 个
验证样本和 48 个测试样本；每程序按冻结哈希选择两个验证/测试样本，因此本轮公开
验证实际覆盖 16/48 项，神经测试查询为 0/48 项。

模型宽度 32，红区深度 2，共 78368 个参数。所有训练使用同一个种子 20261029。
初始 512 步未拟合训练集后，增加两组同预算的 4096 步对照：原 balanced 损失与
直接优化单次编辑位置排名的 ranking 损失。它们使用相同初始化、样本顺序和学习率；
第二个对照再将整个替换字节预测改为 XOR 位翻转预测，保持参数数目不变。这些是
单种子、公开奖励反馈后的跟进实验，不能当作多种子稳定性或独立预注册证据。

`DeltaRGBPolicy` 只把实际损坏输入的位用于输出表示转换，位置和翻转位均由网络学习。
没有提供干净字节或反向位翻转规则；旧 RGB 检查点的语义及默认加载器保持原样。

验证先比较未训练权重与候选的蓝区一次动作：候选必须在损坏样本上至少达到 25% 可见
执行成功率，且严格高于未训练权重，才打开测试集。测试再比较同一权重、同一候选
预算下的原生验证和张量验证；返回的候选仍接受独立原生隐藏输入检查。若验证失败，
保留失败，测试查询数维持为 0。

## 继续实验：先区分复制、证据压缩与条件学习

以下均为同一天的公开验证跟进；旧结论和旧目录保持原样。对 XOR 模型作事后诊断，
在 32 个训练样本与 16 个验证样本中，只轮换四个要求输出、不改变损坏文件和实际
执行结果，最终动作 48/48 不变。最佳候选在 13/16 个验证样本的提议位置预测零位
翻转。这是一个特定干预的结果，不是“网络对任何输出变化都完全不敏感”的证明。

新增 `SingleBitRGBPolicy`：网络在每个候选位置选择八个翻转位之一，训练用分类损失。
参数数目保持 78368，但它显式依赖“恰有一个位错误”的任务约定，不能称为通用
替换字节能力。另一因素把 routed 观察改为 dense 完整注意力，保持网络参数相同。

| 损失与编辑表示 | 观察方式 | 4096 步最好公开验证 |
| --- | --- | ---: |
| ranking，独立 XOR 位 | routed（前轮对照） | 1/16 |
| ranking，独立 XOR 位 | dense | 1/16 |
| categorical，单比特 | routed | 1/16 |
| categorical，单比特 | dense | 1/16 |

四组种子、初始参数、样本顺序和学习率相同；注意力方式和损失的计算成本不同，
这里不作等计算量比较。三组新增实验都未过原门槛，没有查询神经测试。

### 同一个损坏文件必须能对应不同要求

原数据每份损坏文件只有一种目标，允许网络通过文件特征记住修法。新构造只作用于
训练程序：对同一损坏字节的其他单比特修复，接纳四个可见输入均完整运行、输出与
原目标及损坏程序都不同，并与独立原生执行一致的新目标。隐藏输入不用于构造。
67 个损坏文件得到了 119 个附加请求，连同原请求形成 186 个互相需要区分的任务；
另有 29 个原始训练文件没有附加请求。总训练池为 215 项，验证与神经测试池保持原样。

构造用了 1454 次张量执行与 476 次原生执行。不能被当前核心完整执行、或未产生新
可见行为的备选仍计入构造排除项。这是人工单比特错误分布下的合成对照，不是用户
实际缺陷数据。模型输入没有目标文件、错误位置或修复位，干净目标仅用于监督与计分。

这个数据上，完全忽略要求输出、每个损坏文件只给出同一个动作的策略，最多同时
满足 67/186 个成对任务：每组目标的可见输出不同，同一候选无法同时满足两个目标。
这是对这些固定任务的条件上界，不是对所有程序修复器的普遍上界。

先用原来的逐项随机抽样训练 4096 步，最好公开验证仍为 1/16。最终权重在 67 组中
全部给出相同动作，精确恢复 58/186 个目标。随后固定按 ID 选第一对任务，分别从零
和从该最终权重开始，每步同时监督两个请求。两种初始化都在第 128 步达到 2/2，
并保持到第 1024 步；四份最终候选的 16 个可见原生检查全部通过。

这个容量对照只说明当前结构能记住一对需要不同动作的训练请求。它否定“这种网络
完全无法利用要求输出”的强断言，不能作为泛化成绩或升级后的成功率。

### 配对批次与打散批次

接下来的对照只用上述 67 个成组输入。两组分别固定 4096 次更新、每批两项、共
8192 次样本曝光、相同初始权重及损失。配对组把同一文件的不同请求放在同一批；
打散组只将第二列样本循环平移一个批次。两组的逐项出现次数完全相同，顺序哈希
不同。预先冻结的曝光计数哈希均为
`eae5db1c2e6c5f0d08dce1d2a34c817fd8e81a16a15b7319c2a333b6d617bfcc`。

神经测试；通用 evaluate 入口也在加载候选前检查这个限制。

两组最终权重的训练诊断如下。它们的最好公开验证都仍为 1/16，验证选择的候选
均停留在第 256 步；下表使用固定第 4096 步权重，不能偷换成验证选择后的成绩。

| 训练集诊断 | 同文件配对 | 第二列打散 |

## 复现入口

所有输出目录必须为仓库外的新路径。先运行源码检查：

```bash
uv sync --locked
uv run --locked python tools/check.py
```

冻结并差分执行：

```bash
uv run --locked python archive/research/tools/probe_exact_x86.py prepare --out "$OUT/core"
uv run --locked python archive/research/tools/probe_exact_x86.py evaluate --out "$OUT/core"
```

通过后构造新修复语料、训练并按门槛检查：

```bash
uv run --locked python archive/research/tools/research_exact_repair.py prepare \
  --out "$OUT/repair" --parent "$OUT/core"
uv run --locked python archive/research/tools/research_exact_repair.py train --out "$OUT/repair"
uv run --locked python archive/research/tools/research_exact_repair.py evaluate --out "$OUT/repair"
```

复用经哈希验证的任务池进行公开验证跟进时使用新目录：

```bash
uv run --locked python archive/research/tools/research_exact_repair.py refreeze \
  --out "$OUT/ranking-xor" --parent "$OUT/repair" \
  --steps 4096 --objective ranking --edit-encoding xor
uv run --locked python archive/research/tools/research_exact_repair.py train --out "$OUT/ranking-xor"
uv run --locked python archive/research/tools/research_exact_repair.py evaluate --out "$OUT/ranking-xor"
```

如果父实验已经查询神经测试，refreeze 会拒绝把它重新包装成新的盲测。

在尚未查询神经测试的父语料上复现条件训练对照：

```bash
uv run --locked python archive/research/tools/research_counterfactual_repair.py prepare \
  --out "$OUT/conditional-data" --parent "$OUT/repair"
uv run --locked python archive/research/tools/research_counterfactual_repair.py refreeze \
  --out "$OUT/paired" --parent "$OUT/conditional-data" --batching paired
uv run --locked python archive/research/tools/research_counterfactual_repair.py refreeze \
  --out "$OUT/shuffled" --parent "$OUT/conditional-data" --batching shuffled
uv run --locked python archive/research/tools/research_counterfactual_repair.py train --out "$OUT/paired"
uv run --locked python archive/research/tools/research_counterfactual_repair.py train --out "$OUT/shuffled"
```

每个历史目录保存自己的源码和协议；复放旧结果应在独立 checkout 中叠加对应源码
快照，并使用冻结的 `uv.lock`。不要在当前开发目录覆盖源码以绕过身份校验。
