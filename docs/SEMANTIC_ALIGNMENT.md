# 外部代码与说明的语义对齐实验

## 为什么换训练目标

原 Any2Any 训练把输入字节本身作为答案。即使重建准确率达到 100%，模型也可能只是
复制输入；这个指标无法证明它能解释行为。旧解释器的多次乱码输出与此一致，但不能
据此推断换一个目标就一定能成功。

另一个可直接复现的缺陷是请求词序丢失。原实现平均所有请求字节的嵌入，因此
`replace alpha with beta` 与 `replace beta with alpha` 的表示只有浮点舍入误差。
回归测试修复前的最大差异为 `8.344650268554688e-07`，未通过 `>0.001` 的检查。
新训练使用 GRU 按顺序编码请求；旧权重通过显式 `request_encoding=mean` 保持原计算，
不为旧权重偷偷加入随机层。这项修复只证明模型能够区分词序，不证明已经理解请求。

## 冻结协议

实验时间：2026-10-26。目录：
`/home/lightjunction/Documents/LightNest-artifacts/2026-10-26/semantic-v4/`。

从 `/usr/share` 和 `/usr/lib/python3.*` 的真实 Python 项目提取函数与第一段文档说明。AST 只用于构造训练与
评估材料；删除输入函数及其嵌套定义的文档字符串，重新序列化也会去掉全部注释。
模型读取完整函数字节，不读取路径、AST、文档标签或正则提取结果。当前只接纳不超过
1,024 字节的完整函数，较长函数排除，不截断。

| 划分 | 可用函数 | 本轮评估 | 项目数 |
| --- | ---: | ---: | ---: |
| 训练 | 41,933 | 不用于评估 | 173 |
| 验证 | 9,944 | 512 | 69 |
| 外部测试 | 12,109 | 512 | 63 |
| LightNest 盲测 | 18 | 18 | 1 |

外部项目按项目名的固定哈希划分；整个 LightNest 都不参与训练。跨划分删除完全相同的
代码和说明，盲测优先保留。这里没有完成近似克隆检测，不能声称排除了所有相似代码。
`protocol.json` 固定输入、源码和依赖哈希，`source/` 保存实现快照。
验证与外部测试先按代码哈希排序，再按项目轮流抽取 512 项，模型推理前即固定。
完整候选池保存在 `validation_pool.jsonl` 与 `test_pool.jsonl`；本轮分数只覆盖抽样集合。

同一个 `ArtifactCore` 编码代码和说明，用双向对比损失拉近正确配对、拉远批内其他配对。
这替代了只奖励字节复制的目标，不调用外部语言模型。每 256 步在验证集上选择候选，
完整训练预算为 4,096 步，每步从训练池抽 8 对；这不表示每个训练函数都被实际采样。
测试集和 LightNest 不参与候选选择。

首轮逐字节注意力运行 `semantic-v1b` 因实际换页开销主动中止，输入和源码快照保留。
v2 的 1,024 步诊断在 138 个验证样本中命中 5 个，同时审计发现一处删除后被提升为
文档字符串的嵌套说明。该轮未查询测试集，权重不晋升。新清洗器把所有独立字符串语句
替换为 `pass`，冻结阶段重新解析每个输入，检查没有剩余文档字符串。

v3 完成系统库补采集并保留全部原始配对，没有训练或测试。v4 在其不变输入上重新冻结
当前实现，使用两层局部卷积后按 8 字节池化，1,024 字节得到 128 个局部表示，再进入
同一个 Transformer 和 Red。局部卷积在不同字节对齐位置共享权重。所有字节都参与
计算，填充在每层被屏蔽；行为测试检查末尾变化仍影响表示，批中更长文件也不改变
同一个短文件的表示。

测试要求在同一划分的所有说明中找出正确说明，分别报告第一名命中率、前五名命中率和
倒数排名均值。对照包含旧字节重建检查点、纯词汇 TF-IDF 匹配和错配输入。相同分数
按候选顺序处理，不能把全部并列第一报告成全部正确。余弦分数不是经过校准的置信度。

本轮验证标准：新模型在外部测试及 LightNest 两组的第一名命中率都超过词汇匹配，且
超过错配输入对照，才算这一研究步骤通过。通过也只证明候选说明匹配，不等于自由
生成解释、理解任意 ELF、实际执行预测或整个“重大突破”目标完成。

## 公开验证结果：未通过

4,096 步训练完成，耗时 1,007.25 秒。验证选择最终检查点 `candidate-4096.pt`，独立加载
后重新计算结果，与训练记录一致。实际采样 32,768 对，涉及 22,701 个不同函数；通过
最终检查点中的随机数状态核对了确定性采样流。

| 方法 | 第一名命中 | 第一名命中率 | 前五名命中率 |
| --- | ---: | ---: | ---: |
| 旧 v12 字节重建权重，使用同一检索接口 | 14/512 | 2.73% | 4.69% |
| 新代码与说明对齐权重 | 55/512 | 10.74% | 22.46% |
| 纯词汇 TF-IDF | 253/512 | 49.41% | 72.07% |

新模型仍明显落后于词汇基线，不能晋升。根据公开验证失败的结果，停止了原计划的
外部测试和 LightNest 盲测，两者查询次数均为 0。本轮没有完成这两组验收，也没有
达到源码理解或二进制行为理解目标。新旧模型同时改变了目标、局部编码和训练数据，
这张表不能把增益归因于某一个单独因素。

命令行实际加载候选权重并返回了 512 个有序分数；固定验证样本的第一名预测错误，
按错误保留。非数组输入和超容量文件拒绝通过检查，读取文件时限制为容量加一字节。
这些是接口检查，不计为模型语义任务成功。201 项本地回归与源码检查通过；没有
运行 CI，也没有重打包或替换之前的自解释 ELF。

关键证据在实验目录的 `summary.json`、`validation-predictions.json`、
`data-audit.json`、`legacy-and-lexical.json`、`final-local-checks.log` 和

## 复现

```bash
uv run --locked python archive/research/tools/semantic_research.py prepare --out /path/outside/repository
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 uv run --locked python archive/research/tools/semantic_research.py train \
  --out /path/outside/repository --steps 4096
```

下面是通过公开验证后才使用的测试入口；本轮未执行：

```bash
uv run --locked python archive/research/tools/semantic_research.py evaluate \
  --out /path/outside/repository \
  --checkpoint /path/outside/repository/training-20261026/candidate-N.pt \
  --baseline /path/to/any2any-104806.pt
```

`N` 使用 `selection.json` 记录的验证集选择，不能按测试结果挑选。单文件匹配入口属于旧版
CLI，已随研究代码归档；当前 `python -m lightnest` 不再提供 `match-description`。
研究数据、训练与汇总评估仍可通过上面的 `archive/research/tools/semantic_research.py`
复现。权重、训练日志和逐条预测都保留在仓库外。

`prepare --from-corpus /path/to/parent` 可重用经过哈希校验的原始配对，记录父协议哈希并
生成新的源码快照。重新冻结不会让已经使用过的测试数据重新变成盲测；本轮父语料 v3
没有进行过模型推理。
