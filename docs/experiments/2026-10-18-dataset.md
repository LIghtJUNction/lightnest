本次完成 C64／RV32 主线的数据标准化、分片加载、扩量生成入口和自动核验。没有启动大规模训练，没有更新模型权重，也没有改写原实验归档。

## 统一的格式与约束

每组分片分成 `inputs`、`labels`、`index` 三张压缩JSONL表，凭记录ID一一对应。输入表只保存机器码、请求、架构及运行约定；正确补丁、目标程序、执行期望放在标签表；类别、构造组、来源、长度和用途放在索引表。五份JSON Schema与 `SCHEMA.md` 已随包交付。

字节偏移统一从0开始；明确小端、32位整数回绕、代码基址和输入／返回约定；限制程序为4到1,024字节、每指令4字节、最多8个字节替换。动作统一为 `EDIT` 或 `STOP`，全部剩余合法修改作为集合保留，不强迫只有一种修改顺序。

构造对、无关扰动、已修复版本和中间状态整组归属同一用途。同一输入对应不同目标，或来源组跨训练／验证／测试时，整组隔离，不自动选一份标签。输入或目标精确重复，以及中和ADD/SUB和末尾返回选择后的重复，会连接为同组。本次冲突与隔离记录均为0；这些规则不是一般语义去重，不消除所有模板相似或寄存器重命名近重复。

有61条编辑记录，在已有有限测试输入上无法观察到返回数值变化。它们保留为指定字节变换监督，同时标记 `numeric_effect_observed=false` 和 `execution_reward_eligible=false`。不能把输出数值未变当成正确修复，也不能仅凭执行奖励晋升。

## 扩大规模所需的代码已经准备

44组对齐分片按构造组边界切开。默认每片目标256条或4MiB未压缩内容，组边界优先，因此是软上限。逐行压缩读取，转换过程使用磁盘上的SQLite索引，不把全部标准化样本转成内存列表。两份小型历史JSON数组保留一次性内存迁移接口，大型新来源必须使用JSONL。

加载器支持按rank与worker分配互不重叠的分片，逐轮打乱自有分片，记录级和字节预算批次级续读。训练接口默认只接受 `train`；评估接口不返回标签。输入提取器拒绝额外字段，真正交给模型的只有 `command` 和 `binary`。文件夹分离不是安全隔离，正式盲测仍需把答案仅挂载给评价进程。

默认均衡采样器每两条取一条EDIT、一条STOP，优先处理上轮误改风险。它是起始配方，不是已验证的最优比例。较少类别会重复采样，重复展示单独记录。分布式训练须固定共同更新次数；已实现游标恢复，但没有保存多进程预取队列，不宣称支持弹性多机精确恢复。

扩量配方位于 `configs/scale-100k-groups.json`：五个既有训练类别各20,000组，计划增加100,000个构造组、400,000条基础任务，派生状态数以实际生成计数为准。分支＋存储、循环＋存储继续不进入训练。生成只写新目录，再经转换与全量验证，绝不覆盖原发布。

**本次仅完成5组扩量接口实测和100,000组配方预览；没有生成十万组，也没有训练十万组。** 当前生成器仍是合成指令变换任务，扩大数量不会自动变成真实项目修复。

## 运行入口

在解压目录执行：

```bash
python verify_release.py
python -m unittest discover -s tests -v
python -m lightnest_data.audit --data data --schemas schemas --deep --out /tmp/dataset-audit.json
python -m lightnest_data.expand --base . --out ../LightNest_scale_v2 \
  --seed 9600100 --namespace scale-v2 --pairs-per-family 20000 --dry-run
```

第三条命令另需jsonschema；原模型批次兼容检查另需PyTorch及先前的C64源码权重包。完整命令和读取示例在 `README.md`，数据字段在 `SCHEMA.md`，扩量后应依次执行生成、构建、全量检查，再启动单独登记预算的训练。

## 范围、许可与下一步

本次整合 C64主线最新难题、旧回放、已公开C64测试、现场新程序回归和新预留集。其他ELF字节补全与CPU跳转预测分支没有混进来，因为任务和成功标准不同。提供了真实项目来源字段规范，但没有迁移这些分支或增加真实开源缺陷样本。

未发现来源的统一可确认许可证，保留 `license_status=unverified`。不擅自标注开源许可证，也未发布到公开数据平台。公开再分发前，需要补齐各来源许可、项目版本和生成代码授权。

下一轮训练可直接使用本版数据与加载器。训练协议仍需明确模型起点、更新数和资源预算，并同时记录成对修复、正确程序误改、旧能力保持与成本。预留集只在候选冻结后评价；评价后即标为已消费。
