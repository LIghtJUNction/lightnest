# LightNest：完整父模型增长、来源监督与实际更新约束

本轮：`growth-20261017-2301`。全部数字来自保存的运行记录和独立审计。表格中 `a / b` 始终依次表示种子 **104729 / 130363**，不是置信区间。

## 结论与接纳决定

**本轮最有效的路线是把原有 graph＋GRU 核心训练为更长的内部推理过程。** 固定32轮没有增加参数，仍为113,138个；相对于冻结的8轮研究父模型，新终测总体成对全对从36/96、30/96提高到80/96、96/96，长链从0/32、0/32提高到16/32、32/32。两个种子均保持192/192正确程序不误修改、128/128旧任务通过。

公开集先选出的固定32轮第3阶段通过了原定独立验收，现记录为**下一轮研究父模型**。这是一条完成独立验收的研究继承关系；候选结构仍由本轮人工预设，尚未实现模型自主提出架构并连续多代接纳的递归自我改进。生产程序没有被替换。

**外推仍不稳定。** 训练复制深度最高9；公开选择包括11；终测15在训练和选择中均未出现。固定32轮在深度11的新程序上均16/16对全对，但在深度15分别0/16、16/16。不能把长链总体收益解释成两个种子都已经稳定掌握未见深度。

## 做了哪些机制对照

### 完整父模型与增长

所有组复制父模型的完整编码器、graph message矩阵、GRU、字节选择/替换头和STOP头。没有像上一轮Transformer替换核心那样丢弃旧核心。8轮基线与固定32轮使用完全相同的可学习参数；区别是每个动作前内部复用同一个F的次数。

零门控额外轮次采用：

`h_next = h + tanh(a_t) * (F(h) - h)`，新增24个a_t初始为0。

零门控注意力与逐指令MLP使用`h_next = h + tanh(a) * branch(h)`；分支内部可归一化，旧路径后面不插入新的归一化。注意力146,611参数，MLP146,613参数，仅差2个。来源头再增加4,097个训练参数，推断时不调用。

出生验证检查64个公开训练状态、两个种子和全部输出位置、STOP及8个replacement bits。三个零门控结构逐张量等于父模型；固定32轮作为非函数保持对照，不宣称出生等价。分支先检查有限值，防止0乘NaN掩盖问题。测试还确认gate第一步可学、更新gate后分支得到梯度，完整checkpoint恢复后下一步参数、AdamW、采样和RNG精确重现。

零门控并不跳过计算；所有额外轮次即使gate=0也执行。本轮没有动态停止加速。门控是每个内部轮次的共享标量，不是与CPU寄存器数量一一对应的状态槽。公开选定stage2的两个门控模型，其24个tanh系数全为正，分别约0.07856–0.07946、0.08153–0.08367；完整数值保存在depth-diagnostics-analysis.json。它们仍执行全部24次更新，不能把系数之和换算为有效轮数，也不能据此宣称自动架构分化已经发生。

### 来源监督

单独teacher从当前训练字节读取每条指令先读后写的定义事件，追踪覆盖写、最后定义和传递祖先，不读取请求标签、target、repair edits或数值结果。二分类辅助头从两个hidden states判断source-event是否流向consumer-event；每个consumer内平衡正负类，半数损失额外强调最终返回consumer。辅助权重0.2。

teacher全量核验4266训练记录、3626唯一程序，覆盖2,409,794个候选事件对、677,521个祖先关系；与从普通直接边出发的独立BFS一致。它监督显式读取结构，不判断x XOR x之类代数抵消后的最小语义依赖，也不覆盖控制流或别名。

训练末100步，attention＋source的返回长依赖recall约81.81%/80.18%，但新终测长链修复仍0/32、0/32。8轮source也没有突破。**可从hidden读出来源信息，不等于动作头真正用它完成反事实修复。** 同CPU下source还减少更新数，当前结果不能当作同更新步的纯辅助损失因果比较。

### 实际参数更新投影

用同批4条旧训练replay求g_old，然后按正常梯度裁剪、AdamW预条件与weight decay形成实际提议`u=theta_after-theta_before`。若`dot(g_old,u)>0`，Project去掉冲突分量；Shadow算同样reference和统计但保留u；Norm-only保留原方向、仅缩到投影后范数。AdamW moments和step按提议推进。

Project实测触发996/2106与984/2009，即47.29%/48.98%。4115步均在记录的参数舍入容忍界内满足一阶约束。旧训练loss定频诊断仍有6/21与4/20次上升，所以不能声称每步真实loss不增。它的终测长链依然0/32、0/32，未成为赢家。

普通AdamW与Shadow共享2328/1900步的采样、记录loss、grad norm和诊断全部一致；后者CPU成本更高。没有逐步完整权重/梯度快照，不把这些标量一致性扩大为所有中间张量位级一致。

## 深度开关：是不是只要多跑几圈

这是6个条件×2个种子，共12次在看到公开结果后固定的**事后公开诊断**，不读取新终测、不参与选择。每次使用同样192公开选择任务＋128旧任务，完整动作重放和第二VM复核。

| 公开诊断条件 | 总成对全对 /48 | 长链成对全对 /16 | 误修改 /96 | 旧任务 /128 |
|---|---:|---:|---:|---:|
| 父权重直接运行32轮，零追加训练 | 6 / 0 | 0 / 0 | 18 / 0 | 91 / 53 |
| 32轮训练后，同一权重只运行8轮 | 12 / 0 | 0 / 0 | 10 / 28 | 128 / 128 |
| 32轮训练后，同一权重运行16轮 | 48 / 48 | 16 / 16 | 0 / 0 | 128 / 128 |
| 32轮训练后，同一权重运行32轮 | 48 / 48 | 16 / 16 | 0 / 0 | 128 / 128 |
| 门控增长后，关闭全部额外迭代 | 18 / 14 | 2 / 0 | 6 / 22 | 128 / 128 |
| 门控增长后，保留全部额外迭代 | 48 / 48 | 16 / 16 | 0 / 0 | 128 / 128 |

结果同时说明：直接给旧权重更多轮次会损害旧功能；经过32轮训练的新权重确实依赖额外内部计算；在这份公开集上16轮已经足够。16轮新终测没有在原计划中预定，因此本轮不把它作为通过终测的加速版本。诊断中同样628次forward，16轮纯网络forward CPU约2.12/2.03秒，32轮约3.83/3.74秒，这是公开集上的观测，不是部署端延迟保证。

`copy_depth`是每段复制次数，不是整个程序的推理步数。teacher给出的有向定义距离与模型双向消息图距离不同，外部每次修补也会改变后续forward的输入；不能用一个有向距离数字直接证明某个固定轮数必然不足。

## 数据、预算与判分

训练：1280新episodes展开3200合法中间状态，加1066旧训练replay，共4266状态。每批精确12新＋4旧，返回反事实对和无关扰动对交替采样。两个种子，各10组，均训练180 process CPU秒，在60/120/180秒保存阶段，合计39,136次更新、3601.241004081训练CPU秒。

计时包括抽样、编码、全部forward/backward、teacher首次解析与缓存/批量化、辅助头与统计、额外reference梯度、更新投影和定频诊断。日志、存盘和评分另计。主训练626,176次样本使用；额外reference forward/backward49,640次；额外旧loss诊断forward1536次。等CPU不等于等更新数：固定32轮819/852次，8轮AdamW2765/2651次。所有轨迹最终都完整跑到180秒。

位置损失最大化所有合法下一修改位置的概率总和，已完成任务的唯一合法位置为STOP；再加2倍bit BCE、0.2返回margin、0.1无关扰动JS，以及启用时0.2来源辅助。优化器AdamW lr0.001、decay0.01、全参数gradient clip2。所有模型沿用同一种子数据流前缀。

新终测三层各128任务：训练范围内的新程序、11/15复制深度长链、新组合（包括4/6个修改的扩展）。每个构造origin含返回选择×无关扰动×修改/不修改共8个相关样例，384行来自48个独立构造origin。不能把384行、96对或两个种子当作独立重复样本；本轮不报告虚假的显著性或置信区间。

严格成功必须精确得到target字节、通过全部有限执行cases并显式预测STOP；总决策上限8（包含STOP），累计修改字节上限8。不该修改的程序，只要尝试过修改，即使被拒绝、最后字节没变，也失去no-op分。网络只读请求和当前字节及普通直接def/use图；没有目标、执行cases、评估反馈或传递closure作为action输入。

## 下一步的具体判断

1. 下一轮增长必须完整保留这次训练后的32轮函数，不能只复制权重再退回8轮。先验证全部动作头和多步行为的出生等价。
2. 优先比较固定16/32/64轮、零门控继续增长、基于hidden状态的真正可停止计算。采用多深度训练和动作一致性损失，检验能否稳定外推到未见深度；需要新的冻结终测。动态停止必须实际跳过计算才能声称加速。现有gate并非ACT。
3. 来源监督若继续，加入head对hidden停止梯度的同计算对照，检验来源梯度对action的因果贡献；更强来源头只报probe指标不够。
4. 递归自我改进需要连续代的完整继承记录、候选提出机制、独立选择与不可由候选放宽的最终验收；本轮接纳只是其中一条成功研究继承关系。真实开源项目对齐仍需引入真实编译产物、控制流、内存/别名和项目级保持测试。

## 与已有研究及协作任务的关系

函数保持迁移和零初始化残差门控分别参考[Net2Net](https://arxiv.org/abs/1511.05641)与[ReZero](https://proceedings.mlr.press/v161/bachlechner21a.html)。共享内部迭代与[Universal Transformers](https://arxiv.org/abs/1807.03819)的研究方向相关；本轮实际核心是graph＋GRU，不是该论文复现。[ACT](https://arxiv.org/abs/1603.08983)是后续真正自适应计算的参考。旧任务方向约束参考[A-GEM](https://arxiv.org/abs/1812.00420)，实际更新使用[AdamW](https://arxiv.org/abs/1711.05101)。这些思想不作为本项目首创宣称。

启动前只读核对了共享云盘：另一协作者正在推进受限x86-64 ELF的trace与共享位置增长。本轮继续RV32依赖追踪，文件采用独立前缀，没有覆盖对方文件，也没有把不同数据、种子和预算的分数混在一起。协作者的[ELF报告](https://drive.google.com/file/d/1JsA51TZzZguus0q3sqLYsJHDSMZ50xew/view?usp=drivesdk)仅作协作范围参考，其数值未在本轮复现。

当前证据覆盖受限、直线、合成RV32程序和有限执行样例，不构成任意输入等价证明，也不构成超过真实开源项目的结论。
