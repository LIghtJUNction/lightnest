# LightNest：递归自我改进与真实项目对齐

日期：2026-10-17，UTC+08。原生实现版本：v4.1。状态：本轮实验与独立盲测已完成，实验子代未替换稳定模型。

## 结果与目标之间的距离

长期目标是让 LightNest 逐代处理更复杂的程序与更大的需求，以真实、高质量开源项目的行为、测试和资源表现作为参照，并在明确指标上尝试超过参考实现。

本轮完成了真实的原生递归实验闭环：父程序内部提出并训练候选，通过固定开发检查后写出子程序并执行它；子程序继承自己的父代状态，实际使用继承经验继续训练，再因没有合格增益而停止。程序有一次开发集上的自主改进，也在独立测试中获得了部分新能力；与此同时出现旧能力回退。这个结果尚不满足持续、可靠的能力增长目标。

真实开源项目基准也已接入并跑通，但当前学习器只能操作短 RV32 窗口，不能把 xxHash 或 zlib 的整个宿主程序作为编辑目标。项目测试通过属于参考基线通过，不能计作 LightNest 已会修改这些项目，更不能计作超越。

## 一、并行实现了什么

本轮三个子 agent 分别负责原生递归实现与数值对照、学习策略与最终盲测、独立进程继承与资源审查。根 agent 集成代码、接入真实项目、合并另一协作者的新版本，并复跑完整测试。

新增 `linux/recursive_nest.c` 与 `lightnest/pack_recursive.py`。一次构建后，训练任务生成、模型推理、候选采样、RV32执行奖励、参数更新、开发集选择、子代写入和下一代执行均在原生程序内部发生。未在每步使用外部 Python 提供动作或奖励。

继承的内容包括全部模型权重、代号、随机状态、学习率、采样温度、参数更新范围、优化器种类、预算，以及64条执行验证过的成功修改经验。SGD 与 Adam 的公式、网络结构、任务生成方式和奖励条件由本轮工程实现提供；程序只在预先声明的候选范围中选择。实际选中的是 SGD，允许650个输出头参数更新，其中648个数值发生变化。107,280个特征提取参数和可执行代码段逐位不变。

Adam 的非零一阶/二阶状态序列化恢复通过了独立数值测试，但本条接纳链没有选择 Adam，其实际步号与动量均为零。这两种证据必须分开。

### 实际发生的代际过程

| 环节 | 实测结果 |
| --- | --- |
| 父代训练 | 2,048个新任务，4个候选策略 |
| 第一轮选择 | 选择SGD、成功经验回放、650参数更新范围；学习率0.001→0.003，温度1→1.3 |
| 子代发布 | staged文件逐字节读回验证，通过后独占发布 |
| 执行继承 | 独立strace确认父程序进入子程序；权重与三块状态外部哈希一致 |
| 经验继承 | 64条成功经验，来自1,143次父代成功修改的固定容量采样 |
| 子代继续 | 回放候选各实际使用继承经验128次；Adam候选使用368次 |
| 第二轮结束 | 所有候选未满足开发集质量条件，记录`no_validated_gain`并停止 |

实际是两个代际程序运行、一个子代被接纳，没有孙代，也没有连续多次能力提升的证据。冻结子代仍可读状态、做推理；内部`--continue`继承原截止时间，不是重新开启无限训练的接口。

两代合计4,096个新训练任务、8个候选。日志中的37,900次正例访问包含Adam批次内样本；实际是12,300次SGD更新加800次Adam小批更新，共13,100次优化更新，不能把样本访问数称为训练步数。

## 三、真实开源项目：已建立可复跑基线

选择 xxHash 和 zlib，是为了从较集中、无状态的哈希处理逐步进入多文件、有流状态和格式兼容约束的压缩库。本轮固定源码版本和归档SHA，不按最新文件时间选择“最好模型”。

| 参考项目 | 源码范围 | 原项目测试 | 追加兼容检查 | LightNest修改候选 |
| --- | ---: | --- | ---: | --- |
| xxHash 0.8.3 | 87个文件，5,440,024字节 | `make -j2 check`通过；sanity输出49,948项通过 | 24/24 | 尚不能提出 |
| zlib 1.3.2 | 254个文件，3,579,037字节 | `make -j2 test`通过，含静态、共享、64位接口检查 | 30/30 | 尚不能提出 |

输入由固定种子产生，从0、1、31、4096字节扩展到1 MiB和16 MiB，分别包含随机数据和重复数据。xxHash覆盖XXH32与XXH3；zlib覆盖压缩结果的独立解码、独立gzip生产者生成数据的解压，以及损坏CRC的正常错误退出。候选若崩溃，不能记作正确拒绝损坏输入；候选失败也不能获得更快的性能分数。

每个大输入重复测量5次，保留原始耗时、CPU、峰值RSS和输出哈希。最终参考测量中，16 MiB随机输入的XXH3中位吞吐约5,553 MiB/s，zlib默认压缩约37.5 MiB/s。它们包含本地进程启动与I/O，测量环境同时有其他实验运行，不能作为稳定硬件榜单，也没有用于宣称LightNest更快。重复数据、不同大小及全部波动范围在`report.json`中。

这里的16 MiB是处理数据大小，不是模型可理解的代码窗口大小。当前模型仍限于256字节RV32代码与96字节指令文本；读得下大文件和理解、修改大程序是不同能力。

基准入口：`experiments/oss_alignment.py`。支持传入兼容CLI候选做公开开发检查；仅CLI通过不能证明整个库兼容，脚本明确不据此自动晋升。真实项目候选的完整上游测试、全新最终测试和独立性能比较仍是后续工作。

官方来源：

- https://github.com/Cyan4973/xxHash/releases/tag/v0.8.3
- https://codeload.github.com/Cyan4973/xxHash/tar.gz/refs/tags/v0.8.3
- https://zlib.net/
- https://zlib.net/fossils/zlib-1.3.2.tar.gz

固定归档、文件清单、全部原始数值和小型日志保存在`work/oss-alignment-20261017/`。可再生的大输入与大块输出未重复塞入归档；固定生成种子、长度和SHA均保留。历史适配器错误也有记录：首轮误解析XXH3前缀及把`-dc`当成minigzip组合选项，后续修复并完整复跑；这些不是参考库失败。

## 四、对增长规模有帮助的其他改动

`BinaryReader`现在支持累计读取预算`max_total_read`，重复读取也计入；超出预算在下一次I/O前明确停止。结构索引、哈希与扫描走同一预算。1 GiB非稀疏文件实验中，64 KiB分块扫描峰值RSS约17.4 MiB；可靠ELF节索引能用567字节定位并读取小程序。索引命中不等于整个文件只有一个程序槽，全局唯一性仍需要扫描。

`simulate_detailed`新增`halted`、`fuel_exhausted`和`rejected`状态，原`simulate`接口保持兼容。10,812项Python RV32与Unicorn对照没有不一致。长列表可能超过原400步燃料，不应与语义错误混为一谈；这也不是本輪短任务遗忘的原因。

配对格式实验还发现稳定模型对全大写指令从64/64跌到32/64；预声明的ASCII大小写与空白归一化在该套768个输入上恢复成功。该实验没有被静默接成全局语义规则，不能把会改变大小写敏感内容的处理推广到任意程序指令。

证据：`work/parallel-round/io/`、`rv32/`与`paired/`。

## 五、下一阶段怎样判断方向真的有效

以下是建议的下一轮研究验收方向，不是已完成结果：

1. **先获得连续的能力增长。** 预先冻结新的训练、开发和最终测试，要求至少三次真实接纳且在新任务上提高，旧任务保持；不同种子独立复现。不能把程序反复启动、参数增加或训练次数增加算作能力增长。
2. **让改进能涉及当前限制。** 现有局部17字节特征和固定输出头无法承担任意全程序关系推理。下一轮需要可扩展的程序区域/数据流表示、结构版本与加载检查，再验证结构变化是否真的帮助未见程序；本轮没有自动结构搜索结果。
3. **逐步接真实需求。** 从真实项目中的单函数或受限缺陷修复开始，再到多个函数、流式状态和模块接口。逐级扩大输入、代码范围、约束数量与资源预算，前一级回归集随状态一起保留。避免仅增加文件大小而不增加语义难度。
4. **在明确指标上尝试超越。** 对相同功能与格式兼容条件，先通过原项目测试和新的独立任务，再比较时间、峰值内存、二进制体积或资源内可完成的需求数。预先指定优化目标、允许代价和性能门槛；在全新工作负载上复核，失败与退步均留档。

眼下优先级是处理新行为与旧修改的冲突，并把候选生成接口接到已经建立的真实项目基准。直接把当前加减补丁训练重复更久，还没有证据支持会自然变成复杂工程能力。

## 六、代码与复现

在解压后的项目根目录运行。已有CPU环境可直接使用Python；重新安装可按README使用`uv sync --extra test`。

```bash
python -m lightnest.pack_recursive work/patch-rl-v2/patch-rl.pt -o dist/new-recursive-parent
./dist/new-recursive-parent --evolve "$(pwd)/work/new-recursive-run" 3 2048 604719 .001
./dist/lightnest-recursive-experiment-child --state
python -m pytest -q tests
```

前两条需使用新的输出路径。也可直接用归档内已构建的`dist/lightnest-recursive-parent`开始新实验。整条原生训练链共享120秒协作式截止时间，上限8个子代、每代2,048个新任务、4个候选、64条继承记忆。SGD每题最多5个去重动作并可能回放一次旧记忆；Adam候选固定400步×32项。`2048`不是总梯度次数。模型窗口256字节、RV32每次执行400步、宿主ELF读取上限64 MiB。

复核本轮已经揭晓的最终测试，可运行下列命令。它不训练也不选择新权重；`--seen-data`可另传训练/开发JSON进行完全重复输入检查，原正式评测的检查清单已经保存在协议中。

```bash
PYTHONPATH=experiments python experiments/native_blind_eval.py --source . \
  --baseline dist/lightnest-recursive-parent \
  --final dist/lightnest-recursive-experiment-child \
  --final-sha256 64924c105bbd792a04742de0bb4fac7cbe0a96f53913aee2318acca6b34b2b2b \
  --dataset work/recursive-20261017/learning/blind.json --output work/recheck-final
```

项目基线的源码解压与运行：

```bash
mkdir -p work/oss-sources

tar -xzf work/oss-alignment-20261017/archives/zlib-1.3.2.tar.gz -C work/oss-sources
```
