# Universal Machine v1

## 目标与当前优先级

长期目标是跨 CPU 架构的机器码理解、行为建模和代码生成。当前优先本机 x86-64；
其他架构通过统一编解码接口接入，训练和执行后端随后逐一实现。
不能把目标清单写成已经测得的模型能力。

## 指令和架构层

- x86 的 32/64 位解码使用 iced-x86，读取原始字节、变长边界、控制流、寄存器、
  内存与标志位信息；遇到其不支持的编码尝试当前 LLVM 解码器。支持范围受两者版本限制。
- LLVM 的注册目标通过 `targets` 动态发现。多架构汇编、反汇编入口共用同一接口；
  不支持的目标、扩展、无效指令或未解决重定位明确失败。
- ELF 按机器类型和函数符号提取代码；这不是通用 ELF 重写器或完整链接器。
- 指令图包含保守的线性寄存器/内存依赖和分支边。它是模型输入特征，不是完整
  的跨控制流别名分析，也不证明程序语义。

后端依据：[iced-x86 官方项目](https://github.com/icedland/iced/tree/master/src/rust/iced-x86-py)、
[LLVM MC 官方文档](https://www.llvm.org/docs/CommandGuide/llvm-mc.html)。

## PyTorch 网络

1. 原始指令字节保留顺序，补齐到每条指令最多 16 个字节槽；字节嵌入与助记符、
   控制流、指令长度和寄存器特征融合，保留每个槽对应的原始字节位置。
2. 请求字节经卷积编码；多个可见输入/输出样例经共享编码和集合池化；架构标识
   单独嵌入。它们共同条件化代码表示，不输入目标或隐藏样例。
3. 全局注意力、固定八轮双向关系 GRU、末端全局注意力形成整段表示。训练配置
   宽度 96、四头注意力；所有参数端到端更新。
4. 每个原始字节对应一个独立编辑 logit 和八个替换位 logit。所有必要修改分别
   接受训练反馈；最严重的错误编辑额外受罚，正确程序训练为全负集合。
5. 一次产生完整修改集合。无剩余修改即 STOP；超过预算、原值修改、非法输出
   编码不会被当作成功。推断不做标签引导搜索，也不执行候选。

以上是 `predict` 纯神经路径。`repair` 在相同神经权重上增加验证式解码：
先检查原程序是否已满足请求自带的全部可见样例；否则从神经提议出发，按编辑
和替换位的不确定性枚举候选。默认最多 256 次候选尝试、16 个可切换事件、3 秒
总预算，每次原生执行最长 0.1 秒；非法编码先拒绝。只有全部可见样例通过才能
返回候选，耗尽预算则明确拒绝。没有读取目标、隐藏样例或按 opcode 写答案。

验证式解码吸收了旧修复实验“中间提议不能当成最终正确结果”的约束。
其收益属于模型与执行工具的组合，必须与纯神经结果分别报告。

当前重写范围是具有固定容量的代码块。编译后的源/目标函数可以有不同的指令
长度，用尾部 NOP 补齐容量后学习完整字节变化；尚不支持任意 ELF 节区增长、外部
符号链接或跨函数重定位。单块最多 4,096 字节、768 条指令和 64 处字节修改。
解码工具自身的代码块上限与模型容量分别检查。

## 现有实验如何复用

旧 RV32 项目只解决受限结构变换。新方案保留它揭示的三个约束：全部必要修改
都要监督、停止必须与编辑集合一致、不得以更快的错误输出宣称加速。

先用既有历史 TRAIN 训练 RPN3 特征与关系核心，再将形状兼容的字节、请求、GRU、
注意力和读出参数用于本机模型初始化。新指令输入层和架构/行为编码仍需训练。
复用张量清单、父模型哈希和本机更新次数单独记录；这不是已完成的 x86 预训练。

历史 TRAIN 程序另外被翻译为独立 x86-64 函数，并用两份原解释器与本机受限执行
逐条核对。新增原生 C 语料则通过 Clang 编译，并与独立 Python 行为规格核对。
公开验证和最终测试使用不同构造组，编译代码哈希跨分区隔离。

## 执行边界

执行器目前只支持 Linux x86-64、三个 uint64 输入和一个 uint64 返回值。
候选在独立子进程中执行，先加载输入，再启用 seccomp；仅允许有限 stdout 写入和
退出，禁止打开文件、网络、fork、exec 与重新映射内存；另有限时、内存、输出
文件大小限制。特权指令、宿主不支持的扩展和非法访问会失败。

这不是全系统 CPU 模拟器，也不表示所有 SIMD、系统、内核或任意函数 ABI 都能
执行。其他架构目前只验证编解码样例，没有训练或执行验收。
