# 从 Token Lab 迁入的实验经验

2026-11-13 迁入；实验测量发生于 2026-11-12。这里记录的是合成任务上的观察与可复现对照，不是 LightNest 的 ELF 生成成绩，也不是已接入的默认模型能力。

## 对 LightNest 有用的结论

1. 动态边界可以在没有边界标签的情况下学出来，但“出现有意义的切分”不等于“可靠保存了块内信息”。
2. 只统计逻辑块数、状态写入次数或未来位置覆盖率，都不足以证明端到端加速。
3. 多距离预测提供额外监督，但独立的未来边缘预测不会自动组成一致、可执行的计划。
4. 复制、常见模板和最近值规则可以制造看似不错的成绩；必须同时看完整任务成功率和简单规则基线。
5. 逐 token、块级、整句级表示是不同研究对象，不能用相近整句向量替代严格的逐位置实验。

## 一、无 Q/K/V 的动态分块

### 机制与证据

原型使用快、慢两个 GRU 状态。快状态逐 token 更新；学习门决定是否结束当前块、写入慢状态并清空快状态。输出读取本步快状态与更新后的慢状态，再清空快状态，因此未结束块也能逐 token 输出。它不包含注意力、Q/K/V 或增长式 KV 缓存。

三组均为 35,915 参数，训练 800 步，批量 16，配对种子 1/2/3。任务输入 3～6 条变长键值记录，夹杂无关符号，最后询问三个键的最新值。普通测试与长干扰测试各 96 例，各组共用测试集。测试将自己的答案送回状态，不使用真实答案补齐前缀。

| 机制 | 普通逐题正确率 | 普通三题全对 | 普通慢状态写入率 | 长干扰逐题正确率 | 长干扰写入率 |
|---|---:|---:|---:|---:|---:|
| 普通双层循环 | 37.73% | 4.86% | 100.00% | 40.39% | 100.00% |
| 固定每 8 token 分块 | 37.62% | 2.43% | 11.76% | 37.04% | 12.03% |
| 学习动态分块 | 43.52% | 4.86% | 9.61% | 44.33% | 6.35% |

上表是跨三个种子的均值，不是置信区间或显著性结论。动态组相对固定组并非逐种子都胜出，实际写入预算也不完全相同。

简单规则“每个问题都重复最后看到的值”分别取得 **42.01% / 46.53%** 的逐题正确率。动态组只与该规则接近；三题全部答对的均值没有超过普通循环组，尚未证明可靠的多记录存储。

三个种子都有变长块。种子 1 在普通测试中约 95% 的 KEY 后触发写入，噪声 token 后接近 0%；它倾向在下一条记录开始时提交前一条记录。干扰变长后块也变长，但这些现象没有证明模型保留了全部细节。未提供边界标签不代表没有结构提示：KEY、VALUE、END 都是可见输入符号。

原始证据：[全部种子](evidence/token_lab_20261112/dynamic-chunks/results.json)、[汇总及简单基线](evidence/token_lab_20261112/dynamic-chunks/summary.json)、[未挑选成功案例的边界示例](evidence/token_lab_20261112/dynamic-chunks/boundary_examples.txt)、[历史重载/执行插桩验证](evidence/token_lab_20261112/dynamic-chunks/validation.json)。

### 实现中容易误判的地方

- 边界为二值前向，sigmoid 直通梯度反向。仅答案误差就能给门参数非零梯度；这验证可训练路径，不验证梯度估计无偏。
- 加入写入预算，防止全开或全关；仍需报告实际写入率，而不是只写目标倍率。
- 原型设置最大块长 32。20 步先导曾退化到主要依靠这个强制上限分块；强制规则触发的边界不能冒充学出来的边界。
- STE 训练计算每个位置的慢状态候选，再由门选择；因此慢状态少写不代表训练跳过了相同比例计算。
- 推理确实只对结束块的行执行慢 GRU，历史验证通过执行 hook 核对了行数；但快状态、门、输出头和调度仍有成本，不能把 9.61% 写入率叫作十倍解码加速。
- 三组都是固定大小循环状态，固定内存不是动态分块相对普通 GRU 的独有优势。定长状态也不能无损保存任意长随机文本。

### 与 LightNest 现有实现的对应

[现有 H-Net 实验](HNET_PILOT.md)已经区分逻辑分块、批内补齐工作量和实际 CPU 时间；其多种子结果同样不支持稳定生成优势。新证据与它相互补充，但任务、模型、种子和评价标准不同，不能合并为一张性能排行榜。

| LightNest 位置 | 可以迁入的检查 | 目前状态 |
|---|---|---|
| [H-Net 入口](../lightnest/architecture/hnet.py) / 工作区 `wgt/hnet/model.wgt` | 对照直接边界门、固定分块和不压缩；核对跨调用真实末状态 | 现有实现保持原样；本次没有替换架构 |
| [H-Net 训练实验](../lightnest/training/hnet_experiment.py) | 配对种子、最后检查点、完整 ELF/停止正确率、实际分配位置数 | 作为下一轮设计约束，不把合成正确率当 ELF 验收 |
| [上下文预算](../lightnest/architecture/context.py) | 噪声、覆盖旧值、精确字节/常量回忆及简单规则基线 | 需要另外接入 LightNest 的任务派生目标 |
| [训练入口](../lightnest/training/training.py) | 把预测、内存保真、速度分别验收 | 本次未新增训练默认项 |

注意：当前 LightNest 的 H-Net 路由有名为 query/key 的线性投影，用于相邻状态的局部边界评分，不是完整 token 两两 Q/K/V 注意力。Token Lab 原型则连这类 q/k 路由也没有，使用状态拼接后的标量门；两者不能因“都分块”就视为同一实现。

## 二、指数间隔未来预测

共享两层因果 Transformer，宽度 64、128,256 参数。训练三组：下一 token；连续未来 1～7；指数未来 1/2/4/8/16/32/64。每组 1,200 步、批量 32、三个配对种子，每类测试 256 例。该实验的 Transformer **使用 Q/K/V**，与上一节无注意力原型分开，不满足无 Q/K/V 架构约束。

总损失为 `L1 + mean(L_aux)`，每个头按自己的有效目标数求均值；未给辅助头各加一个完整 L1 权重。各组看同样的输入批次，但不等计算量，远期头的目标位置分布也不同。生成只调用下一 token 头，一次追加一个 token。

| 目标 | 延迟复制完整正确率 | 深度 3 选路第一步 | 完整路径 |
|---|---:|---:|---:|
| 下一 token | 100.00% | 3.12% | 0.13% |
| 连续 1～7 | 69.27% | 3.12% | 0.13% |
| 指数间隔 | 68.49% | 3.39% | 0.00% |

指数组复制成绩跨种子为 7.03%～100%，波动大。选路第一步接近从 32 个节点均匀猜测的 3.125%；若读懂起点的四条分支后随机选一条完整路径，本来就可达 25%。三组都没学会这个任务，所以不能据此否定或确认长远规划收益。

补充深度 2 对照只有一个配对种子 4：普通完整路径 2.73%，指数组 4.69%，复制均为 100%。这是探索性观察，不混入主实验均值。

原始证据：[主实验逐种子](evidence/token_lab_20261112/multihorizon/results.json)、[主汇总](evidence/token_lab_20261112/multihorizon/summary.json)、[补充实验](evidence/token_lab_20261112/multihorizon-depth2/results.json)。

## 三、预测重叠不等于可以直接复用的解码结果

位置覆盖只是草稿覆盖。第一次的 `p(x2 | x0)` 与追加 x1 后的 `p(x2 | x0,x1)` 条件不同；早先的预测可以当候选，不能当已经按新前缀计算过的正确结果。远期输出 logits 也不是该未来 token 的真实循环状态或 KV 状态。

可测试方向：缓存候选，补齐连续草稿，用目标模型验证，接受正确前缀，失配后丢弃受影响的缓存。需要单独记录候选命中率、接受长度、验证次数、撤销成本、峰值内存和端到端时间。贪心与随机采样的正确性协议不同，不能用简单 top-1 相同替代采样分布校正。

无注意力循环网络逐步验证仍有状态依赖，不能把 Transformer 对已知候选序列的并行验证收益直接搬过来。这两项原实验都没有实现候选缓存解码，也没有测出这方面加速。

## 四、表示与验收的经验

- token ID、原始 token 字节、模型 embedding 是三种不同对象。十六进制字节不是 ID 的十六进制。
- 替换必须用与权重词表配套的 tokenizer；不能把 o200k_base 的 ID 索引到 Qwen embedding。
- 逐位置局部近邻不是整句同义改写；本轮实际近邻出现“懂 → 不懂”。同一语境里常出现的词并不保证意思相同。
- 若要求 N 个 token，既检查替换数组长度，也检查输出文本重新编码后仍精确对应替代序列；字节片段和重新合并都可能破坏这一要求。
- RoPE 的数值几何验证只说明旋转性质，不证明语义或任务能力；模拟向量不能叫真实模型的原始 embedding。

## 下一轮在 LightNest 的验收顺序

1. 先用符号解析器给出 100% 的任务上限，并运行最近值/复制/固定位置等简单基线；神经模型需超过这些规则，才谈复杂记忆收益。
2. 采用同参数配对对照，并匹配实际写入预算；报告全部种子和完整任务结果，不挑单次成功。
3. 无 Q/K/V 方案应在 WeightLang 架构源中单独接入，保留显式快/慢状态及 train/eval 语义；验证流式与整段输出、边界梯度、跨调用末状态和保存/恢复。Python 研究脚本不是 LightNest 架构真相源。
4. 对随机常量、精确字节、覆盖旧值和更长干扰做盲测，再转入完整 ELF 及行为执行验收。
5. 最后才测速度：区分逻辑写入、实际批内工作量、训练/解码时间；保真、正确性与速度分别给结论。

## 复现与来源

独立控制实验源码位于 [tools/research/token_lab](../tools/research/token_lab)。它们是历史研究对照，不由 LightNest 包或默认训练器导入。没有迁入模型权重、缓存或本机分词词表，也未改动项目依赖。

历史测量使用系统 Python 3.14 / CPU torch 2.15；目标项目当前为 Python 3.13 / CPU torch 2.13。迁移后的短烟测只验证目标环境能运行及机制检查通过，不保证不同版本重训逐位复现历史分数。

在 LightNest 根目录，使用已经安装好项目依赖的环境运行：

```sh
.venv/bin/python tools/research/token_lab/check_evidence.py
.venv/bin/python tools/research/token_lab/dynamic_chunks.py --steps 800 --seeds 1 2 3 --eval-size 96 --output .cache/token-lab/dynamic
.venv/bin/python tools/research/token_lab/verify_dynamic_chunks.py .cache/token-lab/dynamic
.venv/bin/python tools/research/token_lab/multihorizon.py --steps 1200 --seeds 1 2 3 --eval-size 256 --output .cache/token-lab/multihorizon
```

[证据清单与 SHA-256](evidence/token_lab_20261112/manifest.json)记录原始文件到目标文件的映射。数值、每个种子、配置和边界示例一并保留，汇总可从逐种子记录重新计算。证据目录不含历史 `.pt`，因此重载检查需先在缓存目录重新训练生成权重。

相关原始研究：[H-Net](https://arxiv.org/abs/2507.07955)、[Hierarchical Multiscale RNN](https://arxiv.org/abs/1609.01704)、[Multi-token Prediction](https://arxiv.org/abs/2404.19737)、[Speculative Decoding](https://proceedings.mlr.press/v202/leviathan23a/)。这里的本地测量不能替代这些论文各自的结果。

迁移验收：[目标环境短运行记录](evidence/token_lab_20261112/transfer_validation.json)。两种实验的全部对照组均完成 2 步烟测；动态组的三种模式完成权重重载和实际慢状态执行计数核对。历史文件哈希、20 次运行汇总、文档链接和 source-only 检查通过。
