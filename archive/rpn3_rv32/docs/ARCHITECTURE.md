# RPN3：关系推理与修改集合

## 从既有实验得到的设计约束

Hybrid 的提前停止可能把错误输出变快；必要修改损失实验暴露多个正确位置争夺
反馈；一次性判断头只训练旧冻结特征，仍丢失部分旧成功。RPN3 因此使用固定完整
计算、所有必要修改的独立监督，并端到端训练编码器和关系推理核心。
这是一组待实测的架构选择，不是从旧结果推导出的必然提升。

## 数据如何经过网络

1. 请求 UTF-8 字节通过嵌入和卷积编码。保留 12 种历史请求语法作为输入边界，
   句式表不提供任何修改位置或字节答案。
2. 每条指令的四个原始字节、opcode、funct 字段和寄存器编号分别嵌入。
   正弦位置编码保留指令顺序；依赖图只包含直接语法依赖，不提供返回祖先掩码。
3. 四头全局注意力形成输入上下文。共享 GRU 在双向定义/使用关系上执行固定 16 轮，
   每轮保留原始编码并做 LayerNorm；末端再做一次全局注意力。
4. 每个字节的表示结合所在指令、最终返回指令、请求和字节槽位，产生一个编辑
   logit 和八个替换位 logit。输出可以表达任意字节替换，没有 ADD/SUB 答案表。
5. 固定阈值 0.5 同时选出修改集合。没有剩余修改即 STOP；超出八处修改或提出
   原值修改时拒绝提交候选。一次预测完成整个集合，不复用修改前的隐藏状态去
   自回归生成后续修改。

默认宽度 96、四头注意力、两处全局上下文块。精确参数量和训练条件由每次运行的
`training/<seed>-plan.json` 记录。

## 监督与评价分开

损失分别归一化每条记录的全部正位置和负位置，并对最高分错误位置追加监督；
替换位只在必要修改位置上计算。正确程序直接训练全负编辑集合，STOP 不再依赖
一个与编辑头分离的分类器。训练不使用测试任务、隐藏执行结果或旧成功标记。

推断入口严格只接受 `command`、`binary`。目标、组号、修改标签和解释器输出只存在于
训练或评价。评价同时检查完整字节、主动 STOP、正确程序是否被提出编辑，以及
两份有界解释器的有限样例；通过不等于对所有输入的语义证明。

## 边界

仍是固定长度 RV32 结构变换任务，不是自然语言通用代码模型，不生成 Linux ELF。
计算地址、调用及未实现指令明确拒绝。来自已有程序族的新种子和结构去重不能
证明新算法族泛化；历史公开题只作回归。所有预测是未验证候选，没有自动部署。

活动代码位于 `lightnest_next/`；独立预测不依赖归档架构。
`isa.py` 的语法图和第二解释器从原 runtime 的非神经辅助函数整理而来，保留来源说明。
