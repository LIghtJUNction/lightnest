# 实验经验：做到了什么，没做到什么

## 1. 必须同时看新能力与旧能力是否退步

10,000 组新增训练构造使扩量研究模型在其新预留测试上达到 208/224、214/224 编辑完整成功；但分别仍误改正确程序 5/224、1/224，且完整公开回归丢失旧成功。**训练量提高不能替代逐样例保持验收。** 这些预留题已经使用，下一轮只能当回归。

## 2. 预测“何时停止”比缩短固定轮数更危险

Hybrid v1 的无成本惩罚 RL 模式相对监督切换，在同一新测试上分别从 20→27/128、12→19/128；但相对父模型公开回归分别丢失 596、343 条原本成功记录。简单任务计时达到约 2.21—2.65 倍速度，但混合任务仅约 1.19—1.24 倍；错误早停也可能使耗时降低。**不得将较快的错误输出叫作加速成功。**

## 3. RGB 的快速起草不能直接替换红区

RGB v2 的完整草稿风险判断减少部分误改，却没有增加新测试上的编辑成功数。红区核对可维持离散动作一致，但当前实现反而更慢。减少 Python 调度开销的可选循环后端，在特定公开负载下有约 1.30—1.59 倍单请求时间收益，较适合作为独立工程方向。

## 4. 传输差量与计算缓存必须分开

模板 I/O 实验中，109,272 条合成训练记录的输入与目标字节有 99.195% 相同；已有输入底稿时，输出紧凑差量减少约 96.48% 字节，但加入每条 64 字节哈希等包装后收益较少。模板自制压缩再经 zstd 比直接对原始核心数据做 zstd 略大，不宜替换成熟压缩格式。

精确请求缓存在**人为重复 90%**的受控流上约快 10.42 倍，并不代表训练集中有 90% 重复；静态关系模板缓存只能减少解析成本，不能复用不同机器码的神经结果。模型权重、运行规则、请求内容或租户变化时必须失效。

## 5. 独立核验、冻结与反例比漂亮总分重要

每轮记录种子、训练数据指纹、更新次数、模型哈希、计算条件、公开回归及新冻结测试。必须检查“已正确程序被误改”与“以前成功但现在失败”，不能只看新增修复数量。未经使用的任务才可以称作新保留测试。所有执行只用有界解释器，不在宿主机运行候选。

源报告保留完整统计、环境差异、时间口径、未通过项，见 [实验记录](experiments/)；不要把不同实验分母混算。
