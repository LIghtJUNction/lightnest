# LightNest RGB v0：观察、深算、快执行

## 当前交付状态

这是一个已经接入既有 C64 权重的**同一模型内分工原型**，不是三个外部代理，也不是三个独立大模型。新增源码、可加载的初始化权重、训练入口、机制测试和边界说明已随包交付。

**没有完成正式分工训练，没有新的修复成功率，没有启用蓝区自动放行，没有替换稳定模型。** 默认所有请求仍走完整64轮红区；新增路径不能仅凭随机初值的置信度接管动作。

## 推荐结构

| 部分 | 负责什么 | 不该负责什么 |
|---|---|---|
| 绿区：观察与工作记忆 | 接收信息、保存来源和版本、复用精确重复内容；形成与当前任务有关的短表示，并能回读原始字节 | 不因数值相同就合并不同来源；不把摘要当成原始事实；不自行授予执行权限 |
| 红区：深度求解 | 处理长依赖、来源冲突和新组合；多轮更新内部状态；为复杂修改形成依据 | 不依靠长段自然语言输出假装进行了更多有效计算；不把自己的判断当作验收结果 |
| 蓝区：快速执行 | 用较浅路径完成熟悉的小修改；并行处理互不依赖的输入；只输出必要差量 | 不把高置信度当成正确性证明；不把不同返回来源的程序共用答案；不无条件应用整批补丁 |
| 路由器 | 判断浅路径的错误风险，把需要深算的样例交给红区 | 不只按输入长度或模板命中判断难易；不能把教师一致率当成真实正确率 |
| 外部校验层 | 核对底稿、改动范围、冲突、执行预算及独立测试；失败则不发布 | 不允许模型通过改松评分规则证明自己进步 |

同一请求的路径为：原始观察及精确引用 → 共用编码与少量状态更新 → 绿区摘要 → 蓝区提案 → 路由；拒绝浅路径的样例继续红区计算，保留原始节点以供使用。多个请求可以形成批次，但只有需要红区的子批次进入剩余60轮。

在后续完整设计中，红区应能要求绿区补读指定区域；当前原型还没有实现主动跨文件检索、环境工具调用或大文件的分层摘要。不能把这些设计目标计为已完成能力。

## 已实现的模型结构

- 共用编码与前4轮状态更新来自已有 C64；没有把三份完整模型并排复制。
- 绿区使用8个64维可学习状态槽。查询受当前请求影响，对有效指令形成加权读取，保留到每个原始指令位置的权重映射。原始字节和所有节点继续保留；摘要不删除完整输入。
- 蓝区从第4轮状态和绿区摘要读取信息，使用独立的字节修改/STOP输出头。输出头从父模型复制，新增记忆连接仍需训练。
- 红区沿原本未被蓝区改写的第4轮状态继续60轮，复用原来的更新模块与输出头。红区目前仍是受限RV32图循环，不是新的通用Transformer，也不能回答任意程序解释问题。
- 路由器输出一个可训练的浅路径错误分数。默认关闭自动放行；分数还不是校准后的概率。
- `RGBNetwork.forward_train` 同时计算两条路径，用于监督训练。`RGBNetwork.forward` 使用实际子批次分派，接受蓝区后不再计算该样例的红区。

| 子模块 | 参数量 |
|---|---:|
| 继承的红区及共享编码/更新模块 | 113,138 |
| 绿区摘要 | 12,928 |
| 蓝区输出与记忆读取 | 26,891 |
| 路由器 | 4,257 |
| 合计 | **157,214** |

参数统计中的红区包含共享编码与前4轮，并不意味着蓝区另有一份113,138参数的编码器。第一阶段冻结这些已有参数，只训练绿区、蓝区和路由器。

## 信息不能在“抽象”时丢失

`rgb/evidence.py` 是神经处理前的精确观察账本。它只复用相同命名空间内逐字节相同的载荷，仍为每次观察保留独立事件、来源和版本。不同来源即使内容相同，也有各自的引用；同一来源版本出现不同内容会报冲突；超出容量时明确拒绝，不能静默忘掉原始资料。

`rgb/session.py` 将账本接入模型提案缓存。只有命名空间、来源版本、完整请求、完整程序、模型权重和路由设置都一致，才复用结果。更改末尾返回来源不会命中；更新参数也会失效。这个缓存节省的是完全重复的推断，不是近似模板的语义推断。

当前摘要映射指向4字节指令位置。权重图不是已经验证的来源因果解释，8个槽也没有证明能容纳任意大量信息。当前每次模型输入仍受原来的**1024字节**上限约束。账本可以存更多字节，但不会因此使模型理解整份大型文件。

## 蓝区批量执行的边界

先并行处理互不相关的程序，再研究同一程序的一次多处修改。对同一程序，多个修改可能相互影响，不能把几个最高分位置直接合成有效方案。

`rgb/guard.py` 支持对精确底稿的最多8个字节修改进行原子检查：底稿SHA256、旧字节、位置边界、不重叠、不允许把写回原字节算作STOP。仅创建内存中的候选字节，不执行文件、不修改原文件、不宣称通过语义验收。CLI另做受限解析检查，生成的候选仍需独立功能测试。

## 正式训练应分三步

1. **先保住红区。** 冻结既有编码器和红区；让绿区及蓝区学习真实标注。教师只有在当前标签下下一动作正确时，才用于辅助分布学习；教师错误不作为正确答案传播。
2. **再学会交接。** 在蓝区冻结后，用分开的数据校准路由。必须评价完整修改序列、正确程序误改、旧成功是否丢失，不能只看单步是否与红区一致。
3. **最后才联合改进。** 将环境摘要、补读策略、红区计划和蓝区批量动作联训。保留不变的外部验收、资源上限和可回退版本。

具体对照计划在 `configs/phase1_plan.json`。建议至少比较始终红区、始终蓝区、自动路由、移除绿区摘要、关闭精确复用。按相同构造组划分训练/校准/最终测试；旧公开题只能作回归集。观察到的原始环境内容不能自动视为可信训练标签。

没有预报准确率或加速倍数。若浅路径只做4轮，红区做满64轮，忽略其它开销时平均循环次数为 `4 + 60 × 进入红区的比例`；实际总成本还包括绿区、路由、校验、重复提案和失败回退。只减少输出文件大小，不等于减少模型计算。

## 本轮实际检查

- 33项机制测试通过，日志为 `results/unit-tests.log`。
- 两个既有 C64 起点，各使用32条已有TRAIN记录；默认红区输出的所有位置分数和字节分数与原实现逐项一致，共64条记录对比。不是64个独立新程序，也不是修复正确率评价。
- 受控强制蓝区检查确认只调用4轮更新、红区额外调用为0；混合批次中剩余60轮只处理被交接的样例。强制分流由测试指定，不是已训练路由的效果。
- 绿区、蓝区、路由均得到有限的非零梯度。机制脚本对两个起点各试更新3步，已有红区权重指纹不变；默认红区输出仍一致。这些试跑模型没有晋升。
- 正式训练入口另执行2步、每步4条的接线检查。另有一项单元测试执行1步优化器检查；均不属于正式能力训练。
- 保存/加载一个RGB检查点后，全部张量一致，快速路由仍默认禁用。
- 原始输入、来源版本、命名空间、模型参数变化以及错误底稿的隔离检查通过。

`results/mechanism/mechanism-results.json` 含强制路径计时，仅用于排查运行开销。没有在未训练蓝区上做可靠性验收，**不能把这些时间比值当作可部署的加速成绩**。

## 使用

环境已实测 Python 3.13.5、PyTorch 2.10.0+cpu，单CPU线程；不要求GPU，不调用任何外部模型服务。源码未安装第三方代理或后台任务。

```bash
cd LightNest_RGB_v0
python -m unittest discover -s tests -v
python smoke.py --out /tmp/rgb-mechanism-new
```

单次候选提案，默认使用完整红区：

```bash
python -m rgb.cli --checkpoint results/mechanism/rgb-initial-130363.pt \
  --request 'change every add that contributes to the output to sub' \
  --binary HEX_PROGRAM
```

第一阶段训练入口，可直接读取上一版标准化数据的 `data/manifest.json` 目录：

```bash
python train_stage1.py --data /path/to/standardized/data \
  --out /path/to/new-rgb-run --seed 130363 --steps 256 --batch 8
```

该命令是以后可运行的入口；本轮只执行了2步接线检查。它保存模型、优化器、数据游标和随机状态，但还没有提供/验收完整的断点恢复命令。训练中同时计算红蓝两路，不宣称训练本身更快。按分片打乱、片内顺序读取，并不等同于全量均匀洗牌。

初始化权重文件不是已经训练好的RGB专家模型。正式入口输出 `rgb-candidate.pt` 也不会自动启用蓝区放行。当前CLI一次给出一个下一动作；大规模跨文件动作队列和完整计划执行器未实现。

## 研究依据与范围

- Perceiver IO，arXiv:2107.14795：以少量可学习状态读取更多输入的参考。
- Universal Transformers，arXiv:1807.03819：共享权重、多轮内部计算的参考。
- FastBERT，arXiv:2004.02178：较浅出口与教师学习的参考。
- PyTorch官方梯度模式说明：冻结权重、训练模式和推断模式严格区分。

这些是已有研究方法的组合和LightNest特定的工程探索，不主张已发明新的通用认知架构。本轮没有完整论文复现，也不把论文成绩视为LightNest实测成绩。

原始源码与权重来源见 `SOURCE_PROVENANCE.json`，复制文件逐份记录SHA256；沿用来源 `license_status=unverified`，未擅自授予公开再分发许可。所有工作在新目录完成，不覆盖旧模型、数据包或协作者版本。
