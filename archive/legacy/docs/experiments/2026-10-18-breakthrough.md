# LightNest：64 轮训练改善返回依赖追踪，独立验收通过

实验批次：`breakthrough-20261018-0029`；实际恢复训练批次：`20261018-1110`。报告日期：2026-10-18 UTC。

## 1. 结论与实际完成的工作

本轮发现了可以升级实验基线的明显改善：在 **113,138 个参数、每个起点每个方案约 180 CPU 秒的续训预算**下，C64 在独立新终测中的返回来源反事实成对完整修复达到 **444/448、448/448**；冻结父模型是 **136/448、432/448**。两个起点中较差一个由 **30.36% 提高到 99.11%**，提升 68.75 个百分点。

更关键的公平对照是：相同 CPU 预算继续训练 32 轮、推理时也允许 64 轮的 C32，只达到 **224/448、448/448**。C64 在第一个起点新增解对 **220 对**，第二个起点全部保持，没有任何原本成功的编辑任务或返回对变失败。这里的改进超出了本轮“只在推理时增加循环”的效果，不能简单解释为给了更多推理轮数。[终测原始汇总](reporting/final-pairs-summary.csv)、[独立最终审计](eval/final-execution-audit.json)

冻结验收规则已经给出 `promotion_passed=true`，接受两份公开阶段预选 C64 权重作为**下一轮实验的父模型**。本轮共完成 6 种续训方案 × 2 个既有父模型起点，即 12 次训练；计入不同推理深度和冻结父模型，共评测 20 个模型配置。最终选择没有使用新终测成绩重新排序。

这项结果支持“在当前程序依赖任务中，训练模型在更深循环后的状态上做正确编辑与停止，可以显著改善其能力”。它还没有分离长梯度路径、末端监督、不同更新次数及优化轨迹的各自贡献。

## 2. 衡量的是完整修复与来源依赖

每个返回反事实对包含两份数值计算结构相同、最终返回来源不同的程序。要成对成功，网络必须对两份程序都完成对应来源上的全部必要字节修改，并主动输出 STOP；不能只碰巧找到一处加法，或只把执行数值算对。

严格成功同时要求最终字节与参考修改完全一致、有限执行用例通过、网络明确 STOP。已经正确的程序还要求完全没有提出编辑。多编辑任务允许不同的合法编辑顺序；最多 8 个外部动作（包括 STOP）、最多累计修改 8 字节。每次字节编辑之后重新编码当前程序。

模型在动作过程中只接收命令与当前程序编码。评分器预先检查目标长度和测试用例是否存在；目标字节与测试用例不进入 predictor 或 validator。**整个动作序列结束后**才进行目标字节一致性比较与语义执行评分，不用于选择、修正、语义拒绝或终止网络的提议。运行器仅实施字节范围、重复状态和步数等结构约束。执行验证没有进入本轮训练奖励。[固定评分器](../../experiments/architecture_eval.py)、[动作运行器](../../lightnest/iterative_patch.py)

终测每个模型有 1,792 个新任务：896 个需修改任务、896 个无需修改任务；需修改任务组成 448 对返回反事实。另有 128 个旧能力保留任务。所有 20 个模型的 896 个无需修改任务与 128 个旧任务均通过，误改尝试为 0；这两个控制项因此是共同通过的保护条件，不能单独解释 C64 胜出。

对 C64 的实际首步检查还显示，两个起点分别有 444/448、448/448 对在需要编辑时选了不同的首个修改位置；没有观察到首步编辑无关位置、另一返回分支或该返回分支中已经失效的定义。该诊断与完整修复指标相互支持，并不替代完整修复。

## 4. 模型和优化究竟改了什么

当前核心是**带显式直接定义/使用关系图的共享循环 GRU 图网络**。预处理器解析直线 RV32 指令，为每个使用位置连接最近定义，并提供反向使用边；它没有提供目标祖先闭包、正确修改位置或执行结果。模型每轮都重新注入输入表示，并重复应用同一套图消息矩阵和 GRU 参数。

概念上，内部更新为 `h[t+1] = F(h[t], x)`。C32 与 C64 的参数共享方式、字节位置头、替换 bit 头、原 STOP 头相同。C64 将每次训练前向展开与反向传播延长到 64 轮，使用第 64 轮的原任务损失。**参数数量没有增加。**[本轮模型](arch/breakthrough_model.py)、[直接关系图与原始网络](../../lightnest/relation_patch.py)

| 续训臂 | 内部训练与监督 | 实际参数 |
|---|---|---:|
| C32 | `L32` | 113,138 |
| C64 | `L64`，64 轮梯度完整连通 | 113,138 |
| R | 每步按 0.25/0.25/0.5 抽取 32/48/64 轮，用相应末端损失 | 113,138 |
| M | 一次 64 轮展开，用 `0.25 L32 + 0.25 L48 + 0.5 L64` | 113,138 |
| local32 | C32，加 pointer-softmax 局部汇聚后的零初始化 STOP 线性残差 | 113,202 |
| multi_local | M，加相同局部 STOP 残差 | 113,202 |

所有单轮损失保持原配方：合法位置集合监督 + 2×替换 bit 损失 + 0.2×返回来源反事实约束 + 0.1×无关变化一致性。所有臂重新初始化 AdamW，学习率 0.001、weight decay 0.01、全局 L2 梯度裁剪 2、`foreach=False`，batch size 16，其中 12 个主训练样本、4 个旧任务回放。优化器算法没有被这轮结果证明已经创新。[训练源码](optimizer/breakthrough_train.py)、[冻结训练协议](training-protocol.json)

局部 STOP 残差只新增 64 个参数，属于普通 softmax 汇聚和线性残差。它在此次预算与数据下没有胜出。共享多轮监督也没有胜过 C64；不能因机制看起来合理就把它们报告为有效创新。

训练数据保持此前 4,266 个短程序状态：3,200 个主任务状态、1,066 个回放状态；没有增加新的长链训练行，最大程序 352 字节，训练构造深度为 1/3/5/7/9。每个起点的采样流延续此前顺序，六臂共同前缀的实际样本索引完全一致。

| 训练臂 | A 更新次数 | B 更新次数 |
|---|---:|---:|
| C32 | 879 | 883 |
| C64 | 456 | 454 |
| R | 573 | 577 |

全部 12 次训练实际使用 **2161.239905576 CPU 秒**、**7,461 次参数更新**。每次都在首次跨过 180 CPU 秒的更新结束处停止，总超出预算约 1.240 CPU 秒。合计样本使用 119,376 次，其中主任务 89,532、回放 29,844；这些是重复训练暴露，不是新独立样本。batch 级图更新轮数为 349,584。

C64 每次更新更贵，因此在相同 CPU 预算内大约只做了 C32 一半更新。这个设计回答“相同本地训练资源应该花在哪里”；没有同时固定更新次数，不能单独完成 BPTT 机制的因果归因。评测耗时也包括多步程序修复、编码和执行评分；提前 STOP 的失败模型可能更快，不能把它当作相同工作量的推理提速。[独立训练审计](optimizer/training-audit-recovered.json)

## 5. 新验收如何避免循环刷分

公开集使用深度 9/11/15/19；新终测使用 7/13/17/23，后面三个深度超过训练最大值 9。两者都完整交叉 ADD→SUB / SUB→ADD 以及自然长度 / 固定长度。修正这一设计前，旧测试曾把深度 11 只与 ADD→SUB 组合、深度 15 只与 SUB→ADD 组合，无法充分区分深度困难和修改方向困难。[旧诊断复算](arch/diagnostic-findings.md)

终测覆盖复制链、寄存器重命名、覆写使旧定义失效、覆写但保留来源、共享 DAG、双修改、共享覆写等 7 个构造族，每族 2 个随机构造实例，共 **14 个共享构造块**。实际输入 152–488 字节，本轮终测上限为 512 字节；模型配置容量为 1,024 字节。独立从原始字节检查必要定义到返回的有向距离，双修改族最长达到 47 条直接边；网络传递使用双向图，因此不能把 47 直接等同于所需循环数。[终测结构说明](eval/final-release-description.json)

候选角色、阶段、权重、评分器和提升条件固定后，才抽取一次新的 128 bit 数据随机种子。没有筛掉样例、重抽种子或按终测重选赢家。新终测与训练、公开选择集、此前已经消费的终测和旧能力集，均没有相同的命令+二进制输入。

预登记的提升条件要求两份预选模型保持所有无需修改与旧能力案例，并在逐编辑任务、逐返回对上都不丢掉冻结父模型原本成功的样例，至少新增一个成功返回对。还独立报告相对于 C32 续训和额外推理的改善，防止把单纯补训或加计算当作架构胜利。[验收规则](acceptance-rule.json)、[权重与角色冻结清单](frozen-models.json)、[一次终测发布记录](eval/final-data/protocol.json)

审计代理独立复核了 132,754 项训练与预算检查、36 个 checkpoint、公开选择结果及公开执行轨迹。最终独立执行复核覆盖 **20 个模型、38,400 个任务序列、588,688 次第二 VM 执行**，所有绑定与计分一致。这里“审计通过”表示证据与规则检查通过，**不表示每个模型都解对了每道题**。

独立审计仍在同一工作区内运行；它是另一实现的执行器与冻结的评分逻辑，不是第三方机构认证。训练审计没有重算未保存的每步完整梯度，也没有操作系统级文件访问追踪；保存的源码、输入 hash、采样索引和 checkpoint 共同约束实际训练过程。

## 6. 剩余四个失败及其含义

C64 的 A 起点有 4 个编辑任务失败，对应 4 个返回对不完整。全部在 `two_edits / replica-001 / depth23 / SUB→ADD / 返回第二分支`，分别是自然/固定长度与两个无关字节变化的组合。

它们实际上只有 **2 个不同的命令+二进制输入，来自 1 个共享构造块**。深度 23 时自然/固定长度输入完全重复；两个无关变化输入只在 offset 18 不同。四条完整轨迹都只有第 0 步 `model_stop`，没有任何修改提议、接受或拒绝。仍然需要在 0 起始的字节 offset 247、347 各把 `0x40` 改为 `0x00`，即把两条 SUB 改成 ADD。

相应第一返回分支的四个伙伴都修复成功，顺序为 offset 147、47，再 STOP。父模型@32 和 C32@64 在这四个失败输入上也都直接 STOP；它们不是 C64 新增的退化。

C64 保存的 STOP 概率约 0.6043，仍大于所有编辑位置的总概率，因此仅将 STOP 与总编辑概率比较在这些状态上也仍会停止。轨迹没有保存未选位置和 bit 的完整输出，不能断言“去掉 STOP 就能正确修复”。本轮没有据此改阈值或补训终测样例。[失败分析](arch/final-primary-failures.md)、[逐例机器表](arch/final-primary-failures.json)

## 7. 对架构突破、状态槽和递归自我改进的判断

本轮最值得保留的是“训练更深的内部计算”这条实际有效的路线。它为后续架构探索提供了更强父模型和可复核比较流程。当前结构仍是直接关系图加共享 GRU；本轮没有训练新的 Transformer，也没有加入可学习模拟寄存器状态槽。已有 looped Transformer 文献讨论循环外推和停止稳定性，本轮没有直接复现这些论文，也不据此主张算法首创。相关一手资料：[Stabilizing Extrapolation in Looped Transformers via Learned Stochastic Stopping](https://arxiv.org/abs/2606.29983)、[Stability and Generalization in Looped Transformers](https://arxiv.org/abs/2604.15259)。

“数值相同但来源不同”的失败模式说明，状态槽实验应比较它是否帮助保存与使用来源，而不只检查值预测。下一轮已经写成可证伪方案；以下均为**未运行假设**，没有实验分数：

| 假设 | 必要对照 | 不能当作胜利的现象 |
|---|---|---|
| H1：跨过第 32 轮的梯度信用分配有帮助 | 完整 64 轮 BPTT vs 相同 64 轮前向但在 h32 detach；主比较等 CPU，补充等更新/相同批次 | 仅训练损失下降；等更新后优势消失 |
| H2：可学习的来源邻居权重优于固定汇聚 | 已有 def/use 边内的低秩注意力残差 vs 精确等参数逐点 MLP；都新增 2,048 参数 | 注意力图好看，或 MLP 同样有效 |
| H3：跨轮状态槽提供了记忆 | 8 个 16 维持久槽 vs 每轮重置槽；同参数、同读写计算和全局通信 | 槽自己分组，或只改善孤立位置命中 |
| H4：依赖当前隐藏状态的步长有用 | 状态反馈门 vs 只读取固定输入的等参数门 | 隐藏变化量下降但完整修复没提高 |
| H5：角色分组裁剪改善深循环优化 | encoder/core/head 裁剪 vs 精确匹配参数数的随机分组及匹配总范数的保方向控制 | 梯度更平滑，或只有步长缩小而非修复提高 |

每项都必须面对冻结 C64 与同起点继续训练的 C64。H1/H5 先解决梯度与优化归因，H2/H3 再验证来源路由与跨轮状态。H3 的槽数不按某个 CPU 寄存器表定义；网络自行读写，槽不读取目标祖先、正确位置或执行结果。详细配方与失败判据见 [机制与下一轮假设](arch/mechanism-and-next-hypotheses.md)。该备忘录在新终测结果读取前完成，后来单独新增了失败分析。

本轮完成的是**外部编排提出候选 → 训练 → 公开选择 → 冻结后独立验收 → 接受下一轮父模型**。尚未证明模型能够自行提出、实现和持续验证自身架构变化，也没有执行奖励训练的结果。因此不把它称作已经实现递归自我改进。未来每一代都应保留独立验收，不允许候选通过修改评分器取得升级。
