# LightNest：Transformer 架构与底层更新算法对照实验

实验日期：2026-10-17。实验标识：transformer-20261017-1329。

## 1. 结论与实际选择

这一轮已经完成实现、真实训练、公开选优、封存终测和独立执行审计。**按事先冻结的综合规则，选中的是继续训练原关系网络 d8＋AdamW 的第二阶段；本轮没有一个 Transformer 变体达到公开准入条件。** 四个入围 Transformer 中，公开选择集上最值得继续研究的是差分注意力＋Muon，但它仍有明显遗忘和误改。

这次确实增加了修复能力。公开选中的图模型在封存终测中，两个种子的严格修复从原父模型的8/192、2/192提高到128/192、120/192，旧保持题仍为128/128、128/128。返回配对由4/96、0/96提高到36/96、28/96。

同时，**更长依赖链上的返回配对仍是0/32、0/32**；一个选定种子在本应保持的程序上误改2/192。因此，“公开规则选出的候选”与“已经解决依赖追踪、可以零误改自动晋级”不能混为一谈。本轮保留公开选择，未用终测改选阶段4，也未改写共享项目的当前正式模型指针。

实测范围是合成直线RV32程序的编辑定位与补丁执行，不是完整开源项目。当前结果也不是模型自行生成并成功接受多代架构的递归自改进。下面分别说明已完成的比较、得到的证据和仍需检验的研究判断。

证据入口：`result-summary.json`、`public-comparison.csv`、`joint-selection.json`、`reviews/confirm_aggregate.json`、`evaluation/`、`independent-audit.json`。全部分数来自保存的实际模型和执行记录。

### 结果支持什么

图模型的修复增加在封存题上继续成立，且保留旧任务表现。它在分布内和新组合层得到非零的双种子返回配对结果，说明这次补训的收益超过了在新题上一律STOP。但更长链上仍只有一部分单侧修复成功，配对双方全部正确为零；不能只看编辑成功率就宣称已经追踪到了任意最终使用关系。

图模型第二阶段的一个种子误改了2道正确程序，均出现在新组合层。阶段4在此次终测没有误改，但其阶段是终点审计角色，**不能因看到这一结果再把公开选定阶段2换成阶段4**。若将零误改作为自动替换的必要条件，当前选定候选尚缺这项独立验收证据。

差分注意力＋Muon在更长链上有5/32、8/32组返回配对成功，图模型在该层为零；但其整体误改24/192、35/192，旧任务只剩89/128、90/128，新组合严格修复也只有4/64、10/64。这是局部长度泛化信号，应在新的独立实验中检验保守结合是否有效，不能据终测把它重排成当前获胜模型。

### 优化器结论要按实际机制解释

同标准架构、同种子、同学习率档、同初值下，Muon没有稳定优于AdamW。终测编辑为35/192、38/192，而AdamW为43/192、38/192；Muon的旧保持84/128、70/128也低于AdamW的91/128、90/128。这里比较的是两套冻结更新方案在各自CPU预算内的实际收益，不是数学上证明Muon普遍较差。

受限Muon在筛选矩阵中确实触发过限制，累计3742次张量更新；但入围的两个差分长训练中，限制均未触发。同种子B/C共同前缀的样本、各项损失、梯度范数及更新计数相同，限制比例始终为1；受限版本最后少跑89步、125步。没有同一步数的已保存非初始检查点，不能据日志宣称全部权重逐位相同。这组长训练没有检验到“激活限制后是否保护旧能力”，其终点差异包含额外检查成本和不同更新数；共同前缀的完整训练CPU增量尚未分离纯检查开销与执行波动，详见`reviews/muon-cap-inactive-analysis.json`。

配对梯度投影实际完成了筛选更新并触发2553次投影，但没有进入前三探索候选，所以没有长训练和封存终测成绩。应写成在本次短预算筛选规则下未入围，不能扩写成已被充分长训否定。

## 4. 实现了哪些架构与更新假设

六个注意力核心都实际使用Q/K/V注意力，继承的请求编码CNN和输出头仍在；不能称为完全无卷积模型。标准设定宽64、4头、前馈宽128，支持最多1024个程序字节。

| 架构 | 假设与具体实现 | 参数量 |
|---|---|---:|
| Standard | 两个独立PreLN注意力与前馈块，作标准对照 | 146,930 |
| Relation bias | 在注意力中加入可学习的直接定义/使用关系偏置，检验局部结构先验 | 146,946 |
| Reverse query | 第一个块全局编码，再由终止位置的上下文状态反向查询全部程序位置 | 146,930 |
| Shared recurrent | 同一注意力块固定循环4次，检验共享计算；没有学习停止 | 113,458 |
| Differential | 两组softmax注意力之差、可学习系数和逐头归一化，检验抑制公共背景 | 147,122 |
| Centered attention | 从注意力聚合中减去可学习比例的有效位置均值，检验公共背景抵消 | 146,938 |
| 原关系网络d8对照 | 完整继承8轮图推理核心，补足原模型训练 | 113,138 |

Relation bias只读普通解码器给出的直接边，不输入依赖闭包或目标编辑。Reverse query只读终止位置的模型隐藏状态，不直接输入正确返回来源。内部循环数不等于外部补丁决策次数；当前模型未加入数值、来源与使用关系的独立状态槽监督，因此本轮不足以否定那条神经状态路线。

| 更新方法 | 已实现内容 | 需要保留的解释边界 |
|---|---|---|
| AdamW | PyTorch原生AdamW的薄封装 | 正式运行前与原生参数、两个矩状态逐位核对 |
| Muon | 隐藏二维矩阵做动量和Newton–Schulz近似正交化，其余张量用AdamW | CPU FP32实现；两档矩阵学习率0.01、0.02 |
| Muon cap | 在混合Muon/AdamW方案中，限制继承的非向量张量（ndim≥2，包括三维卷积核）每次梯度驱动更新RMS，相对固定初值RMS | 不含权重衰减、不保证累计漂移或行为保持；两个入围长训未激活 |
| Pair projection AdamW | 当配对辅助梯度与主损失梯度冲突时，单向投影辅助梯度，再交给原生AdamW | PCGrad启发的变体；额外反向计算计入CPU预算，非原论文完整算法 |

AdamW及Muon的辅助AdamW学习率两档为0.0003、0.001。权重衰减0.01、梯度裁剪2；Muon动量0.95、Nesterov、5次Newton–Schulz迭代。其余数值及张量分组详见冻结协议和源文件。

六架构×四更新法×两档学习率=48组配置，每组两个种子，共96个筛选运行。两种子是重复实验，不是又增加48种算法。筛选每运行30 CPU秒，长训练每运行240 CPU秒，从相同架构/种子的共同初值重新开始，长训不继承筛选的优化器状态。长训练的四个保存阶段为预算25%、50%、75%、100%；筛选只保存终点，所有运行均完成全预算。

这些组合包含已有论文思想和LightNest专用实现，**不声称学术首创**。差分注意力参考[原论文](https://arxiv.org/abs/2410.05258)，循环共享参考[Universal Transformer](https://arxiv.org/abs/1807.03819)，结构偏置参考[Graphormer](https://arxiv.org/abs/2106.05234)，Muon参考[作者实现](https://github.com/KellerJordan/Muon/blob/master/muon.py)，梯度冲突处理参考[PCGrad](https://arxiv.org/abs/2001.06782)。

## 5. 数据、训练和因果比较的范围

训练集有640个新程序episode，展开为1600个新状态，加533个旧公开回放状态。每个训练批次固定12新＋4旧；完整返回配对与无关扰动配对交替采样。主损失为全部合法剩余位置（或STOP）的总概率负对数（−log Σ_valid p），加2倍替换字节的逐位二元交叉熵，并加入0.2返回配对间隔损失和0.1扰动一致性JS损失。

筛选与选择各128题、16个独立生成来源；终测分布内、更长链、新组合各128题。每个来源产生8个相关变体，不能把所有行当独立伯努利样本来计算很窄的置信区间。两种子也不足以证明跨初始化普适性。三个终测层只有48个生成来源，某些层上的高分应在新生成来源上继续确认。

训练的每段复制次数为1/3/5/7/9，更长终测使用11/15；这不是整条依赖路径的总深度，公开协议中最大必要定义距离由训练29条边扩展到更长层47条边。只有未经修复的原始编辑配对满足两候选分支数值相同、返回反事实只改变最终来源；已修复no-op和非零部分修复训练状态不满足该控制断言。无关扰动保持目标编辑。新组合层将已见原语组合成保留的结构，并加入4处和6处编辑扩展，两者各16题（各8编辑、8no-op）；其余96题仍用已见1/2/3编辑数量与基本原语，并非整层组成原语和所有长度都未见。严格评分同时要求精确目标字节、全部声明VM输入和显式STOP。外部最多8次决策，包含STOP；累计更改最多8字节。最初正确的程序只要尝试编辑就失去no-op信用。

六个Transformer各自精确拷贝79,858个共同编码和输出参数，但替换了父模型的图消息、GRU更新和相关归一化。**张量继承不等于函数继承。** 原图对照保留了完整已有推理核心，因此本轮比较的是具体迁移/继续训练路径在给定资源下的实用结果，不是从完全相同已训练函数出发的纯架构因果比较。架构参数数目也未完全相等，尤其共享循环组更小。

同一Transformer内部的优化器比较使用相同初始文件和种子采样流前缀，但因CPU预算相同，不保证更新数相同。额外反向、正交化和限制检查都需要真实计算。初始化时Standard与Reverse query有相同张量哈希但不同前向配置，整个实验按完整检查点和配置保留身份，没有错误去重。

| H1：保留完整父网络，再增加零门控Transformer支路 | 出生时父输出＋0×支路输出；对比纯父补训、零门控MLP支路、非零门控同结构 | 出生输出不等价即失败；只有旧能力恢复而没有新配对提高，不称新增理解 |
| H2：保留原8轮，学习额外回溯计算 | 新轮以零残差初始化；对比固定8轮、固定最大轮数和相同计算分布的随机停止 | 长链配对仍为零，或总选最大轮数而打乱停止不影响表现，不能称有效自适应 |
| H3：训练时联合监督来源与数值 | 完整父动作路径不变，添加训练期来源头与带已知输入探针的数值头；无辅助、仅来源、仅数值、联合四组 | 辅助头准确但返回变更不改变正确编辑，不能认定依赖已被用于决策 |
| H4：旧训练回放约束实际更新 | 约束包括预条件与衰减后的候选参数变化，额外回放反向成本计入；对比同成本无投影和同幅度裁剪 | 只在参考回放上保持、独立旧任务下降，或收益可由小步长解释，假设不成立 |
| H5：复制完整更新器后学习路由分化 | 专家初始完全相同、归一混合保持父函数；对比单专家、均匀、冻结随机和可学习路由 | 只有专家参数分离/路由熵变化，却不提高严格修复或路由干预无影响，不算有效分化 |

结合本轮证据，优先做H1与H2：前者检验Transformer失败是否部分来自破坏父函数，后者直接对应仍为零的长链配对。H3单独检验来源监督，避免把多个改动同时叠加后无法归因。H4应保护旧行为相关的实际更新，而不是把未触发的RMS限制当作能力保护；H5则应在已有可接受父代上检验真正有用的分化。

函数保持和零残差门已有[Net2Net](https://arxiv.org/abs/1511.05641)、[ReZero](https://proceedings.mlr.press/v161/bachlechner21a.html)等研究，学习计算量已有[ACT](https://arxiv.org/abs/1603.08983)，中间算法监督可参考[CLRS](https://arxiv.org/abs/2205.15659)，旧回放方向约束可参考[GEM](https://arxiv.org/abs/1706.08840)。创新点应体现在LightNest中可验证的组合机制和新的实验结果，不能把这些基础思想重新命名就声称首创。

递归版本需要至少两个连续、成功继承的增长事件：子代确实从当代已接受权重出生，结构改变时保留父函数；候选和拒绝分支均保留；选择器只能读公开反馈；新的独立终测通过后才能替换。还要与等预算随机增长和固定最大结构比较。本轮完成的是人工提出假设后由固定程序执行的架构搜索与一次受控补训，没有声称完成这条递归链。

真实开源对齐应在候选通过依赖与保持检验后逐步接入：先做受约束函数级修复和独立回归，再扩大调用图与需求规模。项目自身测试、外部回归及资源预算都应保留在模型不可改松的验收边界。下一轮需新封存数据，不能继续拿本轮已消费终测选型。
