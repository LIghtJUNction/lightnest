本轮已经实现并实测共享神经寄存器、数据流关系网络、连续字节修改，以及原生大模型学习的计算优化。三个子 agent 分别承担模型结构、动作与独立评估、原生计算与独立代码检查，根 agent 固定数据、统一推断并整合结果。

**没有新模型被晋升为默认，也没有产生通过验证的原生后代。** 原生优化确实让同一个616万参数模型在原有120秒限制内完成四组候选训练；没有候选超过父代并同时保留旧能力。真实开源项目xxHash的配置候选缩小了文件，但未通过原定最终速度门槛，也没有采用。

## 1. 模拟寄存器具体是什么

模型按程序顺序扫描指令。普通RV32解码器给出源寄存器和目的寄存器编号；同一个可训练读写单元读取相应状态，生成新的64维向量，并写回状态槽。这里没有输入程序运行时的真实整数，也没有把加减法执行器作为模型的推理功能。

| 对照 | 跨指令状态 | 模型参数 | float32状态银行大小，每个输入 |
|---|---|---:|---:|
| 无记忆 | 每条指令后丢弃写入，读取全零 | 158,134 | 分配8 KiB零缓冲，但不保留状态 |
| 32槽 | 每个RV32寄存器保留一个最新神经状态 | 158,134 | 8 KiB |
| 128槽 | 每个寄存器保留最新状态和三个旧版本 | 158,134 | 32 KiB |

128槽是32个寄存器的四个版本，不是128个机器架构寄存器。所有槽共享读写网络；新增槽位不增加参数。上表只计算状态向量，不含指令轨迹、掩码、激活、梯度、解释器或模型权重。

每次预测从全零状态开始，重新读取已经修改过的当前程序。因此，它是一次推断的临时工作记忆，既不跨修改步骤保存，也不跨代保存。永久学到的内容仍在checkpoint权重里。

正式训练前修正了一个原型问题：纯覆盖指令不应无条件读取目的寄存器旧值。修正版只有在目的寄存器也是实际源操作数时才保留该旧状态。独立探针确认32槽模型的覆盖后状态、有效后缀及返回上下文不受被覆盖死定义影响；x0不写入，读发生在写之前。128槽则刻意保留历史作为额外上下文，因此仍可能受已无关的旧值干扰。

历史注意力的公开诊断显示，128槽两个种子确实在读取旧版本，但不能据此声称有用。较弱种子仍只输出STOP。第一版原型、修正后pilot、正式训练和全部优化器状态都保留，未把失败试验删除。

神经随机存取记忆和受执行过程约束的程序图网络已有研究先例。NRAM将可学习控制器与可寻址记忆结合；IPA-GNN研究了程序状态和执行路径结构。这里借用的是结构思想，不是对这些论文的完整复现，也没有实现可验证的数值CPU。[1][2]

## 2. 数据流网络与动作层

数据流网络为每条指令建立节点，普通解码得到“该次读取使用最近哪次定义”的边及反向边。共享GRU执行四轮消息传递。局部对照用相同权重形状、相同初始化和相同训练顺序，将跨指令边替换为自连接。每组都是113,138参数。

网络输入包含命令、原始字节及普通指令字段，不包含目标字节、标签、返回可达性答案或测试执行结果。EBREAK读取x10是LightNest VM的返回约定。普通数据流结构提供了比局部字节邻域更直接的程序关系；这类结构在程序图和GraphCodeBERT研究中也有先例。[3][4]

统一动作层让模型每次基于当前程序提议字节修改或显式STOP。它检查原字节条件、重叠、边界、循环和修改预算，记录每步父状态与结果哈希。合法的中间修改可以继续；拒绝候选会保留上一接受状态。接口支持多个字节段和变长修改，但本轮神经模型实际每步只预测一个字节的绝对替换值。

这解除了一次调用只能完成一个编辑的限制。它本身不产生学习：测试时权重始终固定。新图模型与寄存器模型仍是Python/PyTorch模块，尚无原生C打包器。

## 6. 关键诊断：一跳捷径与新的干扰链

公开数据诊断只使用普通最近定义关系、已知任务运算方向和否定条件。规则“源运算的这次定义只要被后续任何指令直接读取，就修改”匹配训练3,520/3,520、开发440/440的完整剩余编辑集合与目标字节。它不需要判断该读取链最终是否到达返回值。

这说明原分布不能充分区分“有消费者”与“影响最终返回值”。这是一项数据性质检查，不是新神经模型成绩，也不证明某个模型内部恰好实现了该规则。

因此另行冻结256题结构压力集。复制链深度为0、1、3、7；每个深度16对程序，形成32道编辑题及32道对应的已修好题。两个候选运算读取相同输入，各有自己的恒等复制链；两个变体只改变最后返回哪条链。深度0保留原一跳线索；深度大于0时，两候选都有消费者，却只有一条影响返回值。

使用原训练寄存器和命令模板，实际84–156字节；配对候选周围±16字节的33字节窗口完全相同。全部5,888个目标执行用例经独立表达式oracle与VM核验，所有编辑题原程序至少有一个用例失败。数据、生成器、评分器和原16个模型均固定后才运行。

**这组压力集是在原实验开展后，根据诊断结果追加设计，属于事后结构压力诊断。它不替代原定848题，也没有触发重新训练、选种子、改阈值或重新选择模型。**

相同验证特征阶段快约1.54倍。两轮完成的工作不同，不能将总用时之比称为同工作量端到端加速。128个输入只需要26次命令编码，复用102次。

父代验证已是63/64。三个SGD候选仍为63/64；400步mask Adam候选降到61/64，因此全部未晋升。四组候选权重摘要均变化，确认更新实际发生，但没有任何后代启动。特征提取器仍被冻结；全输出层可更新5,642参数，mask模式5,130参数，不能把616万总参数都说成在原生阶段接受了学习。

真实width8检查比较1,060,880个浮点值，逐bit差异为零；SGD后完整权重、两步Adam后完整权重与优化器状态也一致。8项窄回归通过。原生结果、测量器、ELF、编译记录、独立旧标量实现、进程追踪与迁移审计均在包内。

## 8. 真实开源项目：xxHash配置候选没有获准采用

基于官方xxHash 0.8.3，实际编译基线与五个候选。仅修改新增配置头中的SIZE_OPT与禁用预取选项，87个上游源文件在六个构建目录中均保持一致。[5]

每个配置通过真实上游检查，其中包含49,948个向量检查，以及136个开发哈希一致性检查。开发搜索接受过一个配置后代，后续被拒绝的候选保留原父程序；完整五段内容继承可重放。这是手写配置枚举，不是神经提案，也没有LightNest权重更新。

所选xxhsum从101,944字节变为94,112字节，减少7.68%；冻结后64个新输入、四种哈希共256/256一致。但原定最终17字节负载耗时比为1.2988，超过1.25上限，最终未采用。

六个配置实际上只有四种不同二进制；SIZE_OPT为1或2时已经禁用预取。相同二进制曾一次通过、一次未通过开发速度门槛，暴露计时噪声。原短测还存在零值与数毫秒离散跳变。

另行冻结的事后计时诊断只重测原基线和原候选：调用数增至64倍，五对交替顺序、单CPU。最短单变体达到0.805CPU秒，没有零值。17字节负载CPU比中位数为1.1951，范围1.0787–1.2849；仍显示变慢，且范围跨过门槛。因此不把原29.9%单点差值描述为精确稳定退化，也不据事后重测改变原采用决定。

本轮没有超越xxHash算法或整体工程实现的证据。

## 9. 独立验证与证据边界

原定终测和公开回归共21,248个episode、47,683个决策，经第二执行器232,406次执行核验。追加压力集共4,096个episode、7,985个决策，独立执行13,455次。相同程序/输入使用缓存复用；这些数值是实际执行次数，不是假定每条记录都独立。

合计25,344条模型评估轨迹全部重放一致。源码、模型、数据协议和结果文件摘要前后不变，训练抽样按种子逐批重建一致。原审计器在追加压力测试时保持原SHA不变，压力审计是另一个程序。原定30个终测/回归结果文件在压力审计中再次确认未被改写。

48项新增模型、动作与评分控制测试通过；另有8项原生窄回归。独立审计器先在公开样本和故意篡改的记录上自检。评分用例、接口测试中的手写预测器及启发式数据诊断都不计作模型能力。

仍需保留的限制：这里只有两个训练种子；核心任务是生成的直线RV32加减程序，无分支、循环、调用或别名内存。虽然用执行用例检查语义，它们不是对所有输入的形式证明。原定扩展任务增加编辑数量和字节长度，却没有充分增加因果选择难度；追加压力集揭示了这点。真实开源部分只覆盖配置选择。当前过程是人设计结构与数据后进行监督实验，尚未建立模型自主修改架构并跨代稳步增长能力。

## 10. 对递归自我改进目标的实际推进

| 层次 | 本轮证据 | 当前状态 |
|---|---|---|
| 一次推断内使用工作记忆 | 32/128槽读写与覆盖检查，完整训练和对照 | 已实现，效果不稳定 |
| 连续修改当前程序 | 神经单字节决策接统一迭代器，记录和重放每步 | 已实现，选择性修改仍失败 |
| 原生权重学习与候选选择 | 同一大模型完成四组真实更新与验证 | 已运行，无有效后代 |
| 跨代继承并变强 | 本轮未接受或exec任何神经后代 | 未建立 |
| 自主探索自身架构 | 本轮结构由人和协作agent编写 | 未建立 |
| 对齐并超越真实项目 | xxHash六个配置实编译，最终门槛拒绝 | 尚未超越 |

本轮后续优先级应放在能辨别最终目标相关性的训练与验证：把有消费者的死链、覆盖后失效的依赖链以及配对返回变化纳入训练；把“完成目标”和“保留无关部分”同时作为约束；在新的未见结构上重新检验同一模型与改进模型。32槽可以继续作为候选工作记忆；图结构提供显式通信，二者是否需要组合应通过新的对照决定。当前没有依据继续堆128、512或更多历史槽并期待自然产生递归能力。

训练时只见过四轮的模型，推断时强行增至八轮会改变其状态分布。后续若研究可变计算深度，应把深度变化和停止策略本身纳入训练与验证，再固定新测试，而非事后挑最好轮数。

## 11. 与共享云盘的另一组实验对齐

开始时核验了09:25版本及其归档摘要；实验期间再次读取共享目录，发现并保留了另一组10:28学习率诊断和10:37数据覆盖报告。

对方报告：width128的学习率降低改善了训练拟合，但新程序泛化没有可靠提升；在相同6,000步下把训练对从64扩到1,024，新的配对全对从18/160降到0/160。数据量增加而更新次数固定，也显著降低每个独特样本的平均呈现次数。它不能证明更多数据在收敛后有害。

这些是对方报告中的结果，本轮没有独立重跑其权重；模型与测试集不同，不能与上表直接比较。其原文件和版本保留，未覆盖为本轮实验。副本与来源记录在 `work/architecture-20261017/collaboration/`。[6][7]

完整交付包含源码、十次正式训练的初始/最终checkpoint及优化器/RNG状态、全部pilot、数据、原定及追加评估轨迹、两个独立执行器审计、xxHash源码与六次实际构建、原生ELF和旧模型依赖。归档附逐成员SHA-256、大小、权限及Git bundle；两个空后代目录也保存。环境运行库需另行安装，未将虚拟环境复制进归档。

仓库内主要入口：

- `lightnest/relation_patch.py`、`lightnest/register_patch.py`：两套训练与推断模块。
- `lightnest/iterative_patch.py`：事务字节动作、循环/预算检查与继承审计。
- `experiments/architecture_data.py`、`experiments/architecture_eval.py`：原定数据与冻结评分。
- `work/architecture-20261017/audit_evaluation.py`：原定结果独立审计。
- `work/architecture-20261017/run_stress.py`、`audit_stress.py`：追加压力推断与原始独立审计；迁移后使用新增的 `portable_stress_audit.py` 入口。
- `work/architecture-20261017/native/REPRODUCTION.md`：原生重建与迁移核验。
- `work/architecture-20261017/actions/`：全部xxHash实验、继承与计时诊断。

从解包后的仓库根目录，在安装项目依赖的Python环境中，可把审计结果写到新的输出目录：

```bash
python work/architecture-20261017/audit_evaluation.py audit --final-complete-authorized --output /tmp/lightnest-architecture-audit-repeat
python work/architecture-20261017/portable_stress_audit.py --repo-root . --output /tmp/lightnest-stress-audit-repeat
python work/architecture-20261017/native/portable-audit.py --repo-root .
```

输出目录必须尚不存在。原压力审计器读取历史绝对路径，直接迁移运行会遇到路径错误；新增入口保留原审计器与原结果字节不变，按完整相对路径及精确锚点迁移记录并逐文件验证摘要。一次独立目录迁移验证重放了全部16×256条已有轨迹，结果与原审计一致，没有重新训练或调用模型。记录在 `work/architecture-20261017/portable-audit-verification/`。源码结果包核验的参数见 `verify_delivery.py --help`。正式训练命令例如：

```bash
python -m lightnest.register_patch --train work/architecture-20261017/data/train.jsonl --development work/architecture-20261017/data/development.jsonl --output work/architecture-new-run/register32-seed104729 --mode register32 --seed 104729 --steps 1200 --batch-size 16 --learning-rate 0.001
python -m lightnest.relation_patch --train work/architecture-20261017/data/train.jsonl --development work/architecture-20261017/data/development.jsonl --output work/architecture-new-run/dataflow-seed104729 --mode dataflow --seed 104729 --steps 1200 --batch-size 16 --learning-rate 0.001
```

使用新的实验目录，保留现有证据。原评分程序拒绝覆盖已有终测目录；再次评估时应在新的输出目录复制相同的冻结inventory、数据协议和输入文件。新的训练或结构若看过本轮压力结果，本轮数据只能作为公开回归集，必须再建新的未见测试。
